# One instrumentation layer

Where a check's time and work went, per module and per declaration, from one
registry, through one flag. Replaces the five hand-rolled roll-up printers and
the four ad-hoc environment switches surveyed in
`issues/perf-instrumentation-consolidation.md`.

The output is **diagnostic, never a gate**. `scripts/bench --check` is what
decides whether something regressed (`docs/benchmarking.md`); this layer is
what tells you *where*.

## 1. Three enablement mechanisms become two

The tree argued both ways — `crates/elab/src/stats.rs` said no feature gate so
that the benchmarked build is the shipped build; `crates/kernel/src/value.rs`
said feature gate so that an ordinary build carries no counted-event branches.
The first argument wins, with the second's concern honoured by *what* is
always compiled:

- **Always compiled, never gated.** Counters are thread-local `Cell<u64>`
  bumps in the kernel and plain `u64` fields on `Eval`; timers are wall-clock
  `Instant` brackets at **phase and declaration granularity only**. A hit
  counter on a conversion query is fine. A timer on every `conv_ty` call is
  not — hits are counted, misses stay timed as they already were.
- **Behind the `value-metrics` cargo feature.** Everything that formats a
  term or captures a backtrace: the `Tc::conv_ty` miss table with its
  first-difference excerpts, `HEATHER_CONV_MISS_TRACE`, the `ValueMetrics`
  cache counters and their collector pointer, the `.conv-miss.txt` sidecar.
  These are samplers, not accounting.

So a shipped build carries the accounting and none of the sampling, and the
build `scripts/bench` measures is the build that ships.

## 2. The kernel's side stays inert

`crates/kernel/src/stats.rs` is a flat list of thread-local `Cell<u64>`
counters with `snapshot()`, `since()` and `reset()`, generated by one macro so
that every counter is declared, bumped and rendered in exactly one place. It
depends on nothing (the kernel keeps zero dependencies, dev-dependencies
included) and **influences no judgment**: nothing in `typing`, `conv`, `eval`
or `reduce` ever reads a counter. Every bump is a one-liner at the site it
describes.

Evaluator counters are the one exception to "thread-local": `Eval::steps` and
`Eval::delta_steps` are plain fields on the run, incremented beside the fuel
decrement they shadow, and flushed to the thread-local totals when the run is
dropped. The fuel decrement is the kernel's hottest line; a field next to
`fuel` costs what `fuel -= 1` costs, and a thread-local access there would
not.

Counters, and where each is bumped:

| counter | site |
| --- | --- |
| `check_terms` | `typing::check_term` and `check_term_profiled`, one per gate call |
| `conv_shortcut_hits` | `Tc::conv_ty`, syntactic reflexivity return |
| `conv_memo_hits` | `Tc::conv_ty`, gate memo return |
| `conv_misses` | `Tc::conv_ty`, every query that pays for a value-domain comparison |
| `conv_out_of_fuel` | a miss that failed for exhausted fuel or depth |
| `conv_not_convertible` | a miss that failed on a real mismatch |
| `eval_steps` | `Eval::spend` |
| `eval_delta_steps` | `Eval::delta_step`, the unfolding branch |
| `eval_drives` | `Eval::drive` re-entry |

The last two rows of the conversion group are the residue
`generated-proof-cost-diagnostics` left behind: a fuel exhaustion and a
mismatch are different diagnoses and must not share a column.

## 3. The registry

`crates/elab/src/stats.rs` — one thread-local registry, replacing
`stats::time_kernel` and `omega_cert::OmegaPhases::timed`, which were the same
function written twice.

```rust
pub enum Timer { Parse, Prelude, KernelGate,
                 DeclType, DeclBody, DeclEmit, DeclCommit, Lower,
                 ElabWhnf, DiagNote, Lint,
                 Unify, Resolve, Matching, Gendefs,
                 OmegaReflect, OmegaSearch, OmegaCutsat, OmegaRender, OmegaParse,
                 OmegaReconstruct, OmegaCheck,
                 ImageDecode, ImageRecheck, ImagePublish, CacheHash, MerkleWalk }

pub fn timed<T>(t: Timer, f: impl FnOnce() -> T) -> T;   // the bracket
pub fn guard(t: Timer) -> Guard;                          // when `f` is awkward
pub fn count(c: Counter);                                 // named elaborator counters

pub fn enable();                       // begin collecting rows
pub fn scope(kind: ScopeKind, module: &str, item: &str) -> ScopeGuard;
pub fn take_rows() -> Vec<ItemTiming>;
pub fn dump(dest: &Dest, rows: &[ItemTiming]) -> std::io::Result<()>;
```

**Nesting rule: timers are exclusive, scopes are inclusive.** A timer running
inside another timer charges only itself: on exit a bracket subtracts the time
its nested brackets claimed, so every timer column is *self* time and the
columns of one row sum to at most that row's `total_ns`. Scope rows are the
opposite and deliberately so — a module row's `total_ns` covers its
declarations, and a declaration's timer columns are its own.

Two consequences worth stating out loud:

- `omega_check` no longer double-counts a certificate that re-invokes `omega`.
  The old `OmegaPhases::check_ns` was inclusive of nested invocations and said
  so; the registry's column is the outer invocation's own share. The
  per-invocation `OmegaReport`s (with `depth` and `used_lemmas`) keep the old
  inclusive semantics and are still drained by `Elaborator::take_omega_reports`.
- A module row's `total_ns` minus the sum of its declarations' `total_ns` is
  module-level work: parsing, import resolution, image decode, replay,
  publication.

**Scopes.** `ScopeKind::Item` is one surface declaration, `Module` is one
module of the closure, `Run` is the whole invocation. A guard snapshots every
timer and counter on entry and pushes one row of deltas on drop. With
collection off, constructing a guard is one branch and no clock: the item
bracket is paid only by a run that asked for it.

Collection is thread-local, so a caller measures the elaborator it drives on
its own thread and nothing else — the property the old `KERNEL_NS`
thread-local already had. The row buffer is capped (a run that forgets to
drain cannot grow without bound) and the cap is reported in the dump.

## 4. One flag, one format

`HEATHER_TIMINGS=<path.tsv>` (or `-` for stderr) turns collection on and dumps
at the end of the run, everywhere: `heather check`, `heather build-x86`,
`heather compile-x86`, and every test binary that used to print its own
roll-up. `heather check --timings <path.tsv>` is the flag form and is what the
primary command gained; `--item-timings` on `build-x86`/`compile-x86` is an
alias for `--timings`, kept because its callers exist.

Environment and flag mapping, old → new:

| was | is |
| --- | --- |
| `HEATHER_OMEGA_PHASES` | `HEATHER_TIMINGS` (the `omega_*` columns; per-invocation lines are gone, the columns attribute by declaration instead) |
| `HEATHER_X86_PHASES` | `HEATHER_TIMINGS` |
| `HEATHER_FUNCTION_IR_X86_TIMINGS` | `HEATHER_TIMINGS` |
| `HEATHER_OMEGA_PREFIX_PHASES` | `HEATHER_TIMINGS` |
| `--item-timings <f>` | `--timings <f>` (the old spelling still parses) |
| `HEATHER_VALUE_METRICS` | unchanged — sampler switch, `value-metrics` feature |
| `HEATHER_CONV_MISS_TRACE` | unchanged — sampler switch, `value-metrics` feature |

The `.conv-miss.txt` sidecar beside a timings file is unchanged.

`HEATHER_GENDEF_DECLINES=1` (`value-metrics`, same rule as the samplers) prints
one tab-separated `gendef-decline` line per *decline* of the generated-
definition devices — site, declaration, reason, declaration scope — because a
device that never registered and one that registered and lost look exactly
alike from outside; group a run with `cut -f2,3,4 | sort | uniq -c`. The
reason is specific enough to act on without re-deriving it from the source: a
hole-match decline names the **former pair** the positional matcher stopped on
(`hole-match-Wf/El`, `hole-match-type-hole/two-occurrences-disagree`), which is
either the next former to teach it or the site where two spellings of one
argument meet.

**TSV schema.** A stable header, tab-separated, one row per scope:

```
scope   module  item    total_ns  <one column per Timer, ns>  <one column per counter>
```

`scope` is `item`, `module` or `run`. `item` is the declaration's name for an
item row and empty otherwise. Timer columns are named for their variant in
snake case (`parse_ns`, `kernel_gate_ns`, `omega_search_ns`, …); counter
columns carry the kernel's names plus the elaborator's own
(`decls_gated`, `gendefs_pushed`, `resolve_goals`, `unify_calls`). The four
`ValueMetrics` cache columns come last and are empty without the feature.

Rows are written in completion order, so a module's declarations precede its
module row and the run row is last.

**Reading it: `scripts/timings <file.tsv> [item…]`,** which looks every column
up *by name* and prints the five that the attribution docs quote — total ms,
gate ms, misses, queries, evaluator steps — plus `--diff a.tsv b.tsv` for
per-item deltas. It exists because the alternative is counting indices off the
header into an `awk -F'\t'` line, which mislabelled three columns in one
session (`issues/timings-tsv-has-no-reader.md`); by-name lookup is also why a
column inserted in the middle is a non-event and the header carries no version.

**`queries` is defined there and nowhere else:** a `Tc::conv_ty` query has
exactly three outcomes — the syntactic shortcut, the gate's cross-head memo, a
paid comparison — so `conv_shortcut_hits + conv_memo_hits + conv_misses` is
every query the kernel was asked, and that is what the column means. The
attribution docs written before this reader quote a "queries" column that is
`conv_shortcut_hits` **alone**; the two are within 1.5 % over a whole run
(memo hits are a ten-thousandth of it) and up to 3.7 % on a single item, so a
number copied from one of those tables reproduces under `--columns shortcut`
and not under `queries`.

Two properties worth knowing before comparing tables. Counts are exact and
**invariant in the worker count** — a run at `--kernel-workers 1` and one at 8
report identical run-row misses, queries and steps, though a handful of
instance declarations shuffle counts between items. Times are not: at width 8
the item rows sum *past* the run row, because each item is charged the wall its
own gate spent and several were spent at once. The reader says so when it sees
it.

## 5. What is instrumented

Elaborator, per declaration (both `elab_module_source` and
`check_module_source` now open an item scope; the latter had only the
sampler's item name and no bracket):

- `parse` — `parse_file`, separated from elaboration on both paths.
- `prelude` — `Elaborator::with_prelude`.
- `kernel_gate` — the finished-declaration gate, the old `stats::time_kernel`
  sites in `lib.rs`, `quote.rs`, `gendefs.rs` and `resolve.rs`, unchanged in
  extent: `elaborate = total − parse − kernel_gate` still means what
  `docs/frontend-benchmarking.md` says it means.
- `decl_type` — a declaration's *statement*: the parameter telescope and the
  result type, from `Cx::empty()` to the elaborated result.
- `decl_body` — its *proof or body*: the statement walk, the checking walk
  against the result type, and goal solving.
- `decl_emit` — turning the checked pair into the pair the kernel is handed:
  the annotation respell, closing the telescope into `Π`/`λ`, and the one
  global substitution that fills the goals.
- `decl_commit` — the registration bookkeeping on the far side of the gate:
  the Ψ push, the name and provenance tables, the module journal's event.
- `lower` — the declaration forms that are not a `fn` (`inductive`, `class`,
  `instance`, `impl`, `datarepr`, `designation`), which lower to a family of
  generated definitions. `gendefs` times *pushing* one; this times building
  them.
- `elab_whnf` — the elaborator's own head-shape probes, at the one chokepoint
  they share (`oracle::SemanticOracle`'s `whnf_*`). Nothing inside a
  `time_kernel` bracket reaches it, so the column is drawn from the elaborate
  side of the split and `kernel_ns` keeps its meaning.
- `diag_note` — elaborator-side conversion run for a *message* rather than
  for a judgement: the checking-mismatch and `refl`-mismatch notes. Counted as
  well as timed (`diag_notes`). The column is what found
  `issues/elab-diagnostic-probe-cost.md`, where those probes ran on every
  candidate of every declaration whether or not it turned out to be fine; they
  now run only where the note is read — at the gate's rejection — so on a
  module that checks, both the timer and the counter are **zero**, and a
  nonzero `diag_note` means a declaration was refused. `diag_candidates`
  counts what was *recorded* instead: the ratio of the two is how much a
  successful build no longer pays.
- `lint` — the per-item source lints.
- `unify`, `resolve`, `matching`, `gendefs` — the entry point of each
  subsystem, not its internals; the exclusive rule keeps a nested entry from
  double-counting.
- `omega_*` — the existing `OmegaPhases` fields, folded in.

The declaration phases are placed so that they partition `check_decl`: what
they leave in `other` on an item row is the retry loop's bookkeeping and the
per-attempt δ-world refresh, and on a module row the import scope, the
container plan and the join.

CLI, per command:

- `heather check`, `build-x86` and `compile-x86` all open a `Run` scope, and
  the native commands open a `Module` scope around the generated certificate.
  Without them the thousands of certificate declarations had rows and no
  total.

CLI:

- `image_decode`, `image_recheck`, `image_publish` — the three phases of
  `SemanticSession::check`, which is what the fast lane's premise rests on
  (`issues/semantic-replay-phase-attribution.md`).

Cache:

- `cache_hash` — declaration identity, the full render of a binding, which is
  the one thing on the gate path that costs real time.
- `merkle_walk` — the interface-closure walk.

Suite:

- `scripts/run-test-targets.mjs` **appends** to
  `target/test-target-timings-<lane>.tsv` with a `run` (ISO timestamp)
  column. Scheduling reads the latest run per target, so the history is
  additive and costs the scheduler nothing.

## 6. Cost when nobody is measuring

Counters: one `u64` increment each, on lines that already touch the cache line
they live on. Timers: two `Instant::now()` per phase entry, where a phase is a
whole declaration gate, one of the four parts of a declaration, a unification,
a resolution, one head-shape probe, one diagnostic note, an omega stage or a
module image operation — never a conversion step, never an evaluator step. The
finest-grained of those, the whnf probe, still brackets a call that allocates a
value arena and runs the machine. Row collection: one branch per scope entry
when off.

`scripts/bench --check` against `crates/kernel/benches/baseline.tsv` is the
evidence; per the repo's policy no concrete numbers live in this file.

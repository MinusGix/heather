The general typeclass/trait feature, designed 2026-08-07 in discussion; the full record is docs/traits-design.md and this issue owns its staging (doc §13). One-paragraph contract: a class is a parameterized record; an instance is a namespace of ordinary declarations plus an assembled record value (block and literal forms, `instance Monoid<Rat>`, no `for`); `extends` is flattening plus ONE CANONICAL VALUE PER (CLASS, CARRIER) — parents filled by reference when declared, synthesized as projections when not, overrides owing kernel-checked agreement proofs; resolution is an ascending-scope, deterministic, mode-directed, structurally-terminating backchainer whose every derivation is minted as a canonical named global (memoization = canonicalization), scheduled on the withheld-obligation machinery, failures returning the search trace as data; instance implicits are the default case of solver-default arguments (`:= infer`); layer 3 re-implements the resolver as a heather function over QUOTED goals when context computation lands.

## Log

- 2026-08-07: Layer 1 landed (doc §13 item (a)): specification slice docs/traits-layer1-design.md; class/instance parse (crates/syntax parser+ast) and elaborate (new crates/elab/src/traits.rs) as pure surface desugaring — a class builds the record an equivalent `record` would and calls elab_inductive, an instance builds ast::Decls (members, value, synthesized parents, agreement certificates) and calls elab_decl, so no kernel change and no new lowering. Block and literal forms, dependent fields, extends with flattening+dedup, canonical parents in BOTH directions (parent-first fill-by-reference, child-first synthesis), overrides certified by a synthesized `theorem …#agrees: over = parent { refl }`, generic instances as dictionary-valued functions with `requires` as explicit params. 31 tests in crates/elab/tests/traits.rs; workspace 1177 -> 1208 fast. TWO CORRECTIONS to docs/traits-design.md, both recorded in the slice §7: (1) §12's content-addressed minting keyed on (class, carrier-syntax) is narrowed at layer 1 to (class, carrier HEAD) — the canonical name has to be spellable (`Rat::Monoid`) for an instance to be usable without a resolver, and a rendered type argument is not an identifier; two carriers sharing a head is a declaration error naming both, and layer 2's canonical-derivation table inherits the full key. (2) A member reference in the assembled value writes its type arguments explicitly (`f<A,B>(ma,mb)`) because the applicator refuses to mix partial application with implicit insertion. Also found: `extends` arguments are restricted to the child's own type parameters (instantiation is then a rename, not a substituting walk) and an instance is all-or-nothing by elaborator snapshot. DEFERRED to layer 2 (slice §8, owner = this issue's item (b)): the full canonical key; receiver dispatch through an instance (member_bases records `Monoid::op`, not `op`, so x.op(y) does not reach a member — concrete-carrier dispatch needs member_head to try T::C::op, generic-carrier dispatch needs receiver sugar to consult dictionaries); fill-by-reference and override agreement against a PARAMETERIZED canonical parent (applying its value is resolution); and making `requires` instance-implicit, which is what turns the cross-member rule from 'pass them' into 'they are found'. One lexer residue: three-segment names (`Rat::Monoid::op`) are registered and resolvable but unwritable (the lexer joins exactly one `::`) — members are reached by projection instead, definitionally the same value.
- 2026-08-07: Layer 2 landed (doc §13 items (b) and (c)): specification slice docs/traits-layer2-design.md; the resolver is new crates/elab/src/resolve.rs plus a ResolveOb arm in apply_implicit's existing retry-to-fixpoint loop — no new scheduler, no kernel change. ONE new parameter kind carries the whole feature: a SOLVER PARAMETER, desugared in the parser from both `fn f<A> requires m: C<A> (…)` and `p: T := infer` to a leading implicit parameter with solver=Infer, so instance implicits and auto-params are literally one mechanism (record §8). Search order: canonical derived table, then locals innermost-first (which is why a cross-member call inside an instance block now FINDS its requires binders and why a plain `let m: Mag<Z> = …` shadows the registry), then the registry by backchaining — where backchaining is just the bare-reference checking route (unifier-completeness §5.3) elaborating the instance global against the goal, its own requires recursing. Termination is Paterson-style structural decrease over the written types, refused at the instance declaration naming the offending binder; overlap is layer 1's (class, carrier-head) key claimed as the overlap check rather than as a naming collision; blocked goals ride Sol::Withheld and report at the call. Failures raise ElabError::Resolution carrying a flat list of (depth, key, value) records — goal/scope/local/class/candidate/rejected/no-class/no-instance — nested subgoal searches spliced in at depth+1: the first consumer of the ai-facing-tooling trace-as-data direction. 21 tests in crates/elab/tests/traits_resolution.rs; workspace 1210 -> 1231 full, lib/ir_v1.hthr untouched. FOUR CORRECTIONS, all in the slice §9 with evidence: (1) candidate selection is by ordered TRIAL verified with typing::check_term at the goal, not by head-keyed matching — the goal arrives lowered and monomorphized, so the carrier is not readable from it without matching the class's surface fields against a Σ; under the overlap discipline at most one candidate verifies, so it is the same function of (goal, scope), and the rejections are what the trace reports. (2) Derived globals are keyed by the goal type UP TO CONVERSION (a scanned Vec) and named by ordinal, not content-addressed: no component can encode a kernel type totally (Debug is budget-bounded by design, and a bounded key is a collision), so idempotence holds within an elaboration and cross-run/cross-module identity is residue. (3) Minting happens BETWEEN items, never mid-declaration — a global reference is GlobalVar(|Ψ|-1-abs+goal_base), so growing Ψ mid-item invalidates every reference already built — which means the FIRST use site of a derivation inlines its copy and every later one references the mint; the rollback-and-re-elaborate alternative was rejected as doubling every item that resolves something new. Only a PARAMETERIZED instance's result is canonicalized: a declared instance is already one global reached by name. (4) A `requires` binder's type is parsed as a class reference, because in front of a parameter list `Mag<A> (x: A)` reads as a value-parameter application. Layer 1's suite stays 31 green with the two edits its own §4.2/§8 predicted (a cross-member call now omits its requires; a generic instance's value is written bare) — the positional spellings became the negative controls. RESIDUE, owner = this issue: MODES (out-params) cut with evidence, not for time — construction checks a candidate against a fully zonked goal, and an output position that is still a meta has no goal to be checked against; making it real needs a nested resolution world plus a learn-only unification back into the caller's scratch world, its own slice. Nothing shipped in the meantime (no syntax that does nothing). Also residue: the agreement-proof escape for overlap (needs two values at one key, which the layer-1 name scheme cannot hold); content-addressed derived names (needs a total structural encoding of a kernel type; interacts with parallel-checking-and-caching); `let instance` as a keyword (the behavior exists for a plain `let`); receiver dispatch through instances (still layer 1 §8's); and trial cost (O(candidates) kernel checks per goal — file per the perf discipline if a corpus notices).

The general typeclass/trait feature, designed 2026-08-07 in discussion; the full record is docs/language/classes/traits-design.md and this issue owns its staging (doc §13). One-paragraph contract: a class is a parameterized record; an instance is a namespace of ordinary declarations plus an assembled record value (block and literal forms, `instance Monoid<Rat>`, no `for`); `extends` is flattening plus ONE CANONICAL VALUE PER (CLASS, CARRIER) — parents filled by reference when declared, synthesized as projections when not, overrides owing kernel-checked agreement proofs; resolution is an ascending-scope, deterministic, mode-directed, structurally-terminating backchainer whose every derivation is minted as a canonical named global (memoization = canonicalization), scheduled on the withheld-obligation machinery, failures returning the search trace as data; instance implicits are the default case of solver-default arguments (`:= infer`); layer 3 re-implements the resolver as a heather function over QUOTED goals when context computation lands.

## What it assumes from elsewhere

- **[[compile-typeclass-design]]** owns the Compile certificate shape and CallCtx. Assumed here: only that an instance's semantics stays 'ordinary record value'. Its §5 class layer is superseded by this design (target indexing struck — doc §10).
- **[[elab-unifier-completeness]]** owns the withheld-slot scheduler. Assumed here: only that deferral-and-retry-to-fixpoint stays available to new obligation kinds.
- **[[generators-in-the-language]]** owns the meta-layer migration and the ch. 07 missing-features list. Assumed here: only that context computation is on that list and enumerable.
- **[[elaboration-determinism]]** (closed, spine recorded on [[parallel-checking-and-caching]]): the resolver must be a deterministic function of (goal, scope).
- **[[ai-facing-tooling]]** owns failure-state-as-data. Assumed here: only the direction.

## Staging

Doc §13: (a) layer 1 declaration forms; (b) layer 2 resolver + `:= infer`; (c) trace-as-data diagnostics; (d) layer 3, behind the meta-layer roadmap. Open questions in doc §12 (termination default's bite, post-hoc registration, mode syntax, canonical-table scope, agreement-proof form).

FOUR CORRECTIONS, all in the slice §9 with evidence: (1) candidate selection is by ordered TRIAL verified with typing::check_term at the goal, not by head-keyed matching — the goal arrives lowered and monomorphized, so the carrier is not readable from it without matching the class's surface fields against a Σ; under the overlap discipline at most one candidate verifies, so it is the same function of (goal, scope), and the rejections are what the trace reports. Only a PARAMETERIZED instance's result is canonicalized: a declared instance is already one global reached by name. (4) A `requires` binder's type is parsed as a class reference, because in front of a parameter list `Mag<A> (x: A)` reads as a value-parameter application. AMBIGUITY RULES, all deterministic, no priorities, all pinned: (1) a field of the receiver's OWN type wins and dispatch is not attempted (surface-records §4.4 — that reading is the receiver's structure, so adding an instance reinterprets nothing); (2) an ordinary type-owned member, a bare name in scope, or a builtin beside a SUCCESSFUL dispatch is an error naming both, with both spellings — member_head's own growth-invariant rule extended, not a new one; (3) two classes with one member name both resolving at the carrier is an error naming both, every candidate tried even after one succeeds because the error is the point; (4) scope beats registry, pinned with a DISTINGUISHING local dictionary (its op returns the other argument) plus the negative control that the registry equation then fails; (5) a failed dispatch removes no reading — silent fallback when another reading exists, the layer-2 trace as the diagnosis when there is none; (6) candidates are exactly the classes a written reference would resolve to (key_of), so an unimported module's class captures nothing; (7) two narrowings refused by name — a bare x.op (no parentheses) never dispatches, and a multi-parameter class says so with the projection spelled. 17 tests in crates/elab/tests/traits_receiver.rs; layer-1 (31) and layer-2 (21) suites green UNEDITED; workspace 1231 -> 1248 full, lib/certgen/ir_v1.hthr untouched. WHAT THE CORPUS FOUND, in order of weight:

1. **An inherited member is undispatchable, permanently** — [[inherited-members-undispatchable]],
   with the decision options. `extends` and receiver sugar exclude each other
   at every carrier, because flattening plus synthesized parents means every
   class in a chain answers for the inherited field. The library's response
   is visible in the code: `Monoid` is declared FLAT, with a comment saying
   why, and the hierarchy's `plus` is always spelled explicitly. This lands
   directly on the operators-migrate-onto-classes direction in §12.
   **RESOLVED 2026-08-08** (owner-keyed dispatch + scope upcast,
   docs/language/classes/traits-owner-dispatch-design.md; that issue is closed): `Monoid` is
   un-flattened and the hierarchy's `plus` dispatches. One standing hazard
   for §12's propositional-override fallback, in the log below.
2. **A generic class lemma dies at a `Wf`-lowered carrier** —
   [[class-lemma-instantiation-fuel]], reproducer and seven probes. The class
   layer buys abstraction for programs but not, at container carriers, for
   proofs. **RESOLVED 2026-08-10:** conversion now recognizes a shared scoped
   type closure by reflexivity, and `lib/std/algebra/algebra.hthr` ships the restored
   generic `concat_single` theorem at `List<A>`.
3. **A member name that collides with an ambient global is undispatchable
   too**, for the same "name both readings" reason — `Cmp`'s field is `le`,
   not `leb`, and `AddSemigroup`'s is `plus`, not `add`, purely because
   `std/nat` already exports functions by those names. Naming a class field is
   a decision about the whole ambient namespace. The diagnostic is good (it
   spells both readings and both fixes); the constraint is the finding.
4. **Two structures on one carrier worked exactly as designed.** `Bool` has
   conjunction registered and disjunction as a named `fn` value; `any_of` is
   `all_of` with a `let`-bound dictionary and the two folds compute
   differently. Nothing about this needed a keyword — the plain `let` is the
   scoped override, which is [[traits]] §10's "the behavior exists" claim
   confirmed at a real use.
5. **Literal-form assembly is the right default for a library**, and by a
   wider margin than the record suggested: every instance here is
   `field := global`, because every fact was already proved in the module that
   owns the carrier, and block form would have moved definitions that other
   files reference. The one thing literal form cannot do is prove something
   new in place; two fields here are inline `λ … => refl` and want nothing
   more. Whether block form atrophies (§12's open question) — not yet: it is
   still the right form when the carrier's module is the instance's module.
6. **Minting is rarer than expected, and correctly so.** A resolution at an
   OPEN carrier is not a closed goal and is never minted, so
   `fn concat<A>(…) { mconcat(…) }` derives nothing and every caller of
   `concat` derives nothing either — the derivation only appears when a
   caller writes `mconcat` at a closed list carrier. Both facts are pinned
   (`a_derived_list_monoid_is_shared_between_use_sites`,
   `calling_concat_derives_nothing`). Worth knowing before anyone reads a
   derivation count as a search-cost proxy.
7. **`:= infer` and `requires` really are one mechanism**, and the choice
   between them is placement: `or_default(o, d: Default<A> := infer)` reads
   better than a `requires` prefix when the dictionary is the trailing
   argument. No difference was observable beyond that. One ergonomic edge:
   a `Default<A>` dictionary cannot help *infer* `A`, so `or_default(None)`
   fails at `None`'s own type argument, not at the resolution.

NO measurable elaboration cost: the two whole-library tests are unchanged
within noise (`--test ir_v1` 63.8s CPU before, 61.0s after — the additions to
`nat`/`bool` are two theorems and a handful of case splits). Full suite green,
1248 → 1266.

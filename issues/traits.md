The general typeclass/trait feature, designed 2026-08-07 in discussion; the full record is docs/traits-design.md and this issue owns its staging (doc §13). One-paragraph contract: a class is a parameterized record; an instance is a namespace of ordinary declarations plus an assembled record value (block and literal forms, `instance Monoid<Rat>`, no `for`); `extends` is flattening plus ONE CANONICAL VALUE PER (CLASS, CARRIER) — parents filled by reference when declared, synthesized as projections when not, overrides owing kernel-checked agreement proofs; resolution is an ascending-scope, deterministic, mode-directed, structurally-terminating backchainer whose every derivation is minted as a canonical named global (memoization = canonicalization), scheduled on the withheld-obligation machinery, failures returning the search trace as data; instance implicits are the default case of solver-default arguments (`:= infer`); layer 3 re-implements the resolver as a heather function over QUOTED goals when context computation lands.

## What it assumes from elsewhere

- **[[elab-unifier-completeness]]** owns the withheld-slot scheduler. Assumed here: only that deferral-and-retry-to-fixpoint stays available to new obligation kinds.
- **[[generators-in-the-language]]** owns the meta-layer migration and the ch. 07 missing-features list. Assumed here: only that context computation is on that list and enumerable.
- **[[elaboration-determinism]]** (closed, spine recorded on [[parallel-checking-and-caching]]): the resolver must be a deterministic function of (goal, scope).
- **[[ai-facing-tooling]]** owns failure-state-as-data. Assumed here: only the direction.

## Staging

- 2026-08-07: Layer 2 landed (doc §13 items (b) and (c)): specification slice docs/traits-layer2-design.md; the resolver is new crates/elab/src/resolve.rs plus a ResolveOb arm in apply_implicit's existing retry-to-fixpoint loop — no new scheduler, no kernel change. ONE new parameter kind carries the whole feature: a SOLVER PARAMETER, desugared in the parser from both `fn f<A> requires m: C<A> (…)` and `p: T := infer` to a leading implicit parameter with solver=Infer, so instance implicits and auto-params are literally one mechanism (record §8). Search order: canonical derived table, then locals innermost-first (which is why a cross-member call inside an instance block now FINDS its requires binders and why a plain `let m: Mag<Z> = …` shadows the registry), then the registry by backchaining — where backchaining is just the bare-reference checking route (unifier-completeness §5.3) elaborating the instance global against the goal, its own requires recursing. Termination is Paterson-style structural decrease over the written types, refused at the instance declaration naming the offending binder; overlap is layer 1's (class, carrier-head) key claimed as the overlap check rather than as a naming collision; blocked goals ride Sol::Withheld and report at the call. Failures raise ElabError::Resolution carrying a flat list of (depth, key, value) records — goal/scope/local/class/candidate/rejected/no-class/no-instance — nested subgoal searches spliced in at depth+1: the first consumer of the ai-facing-tooling trace-as-data direction. 21 tests in crates/elab/tests/traits_resolution.rs; workspace 1210 -> 1231 full, lib/ir_v1.hthr untouched. FOUR CORRECTIONS, all in the slice §9 with evidence: (1) candidate selection is by ordered TRIAL verified with typing::check_term at the goal, not by head-keyed matching — the goal arrives lowered and monomorphized, so the carrier is not readable from it without matching the class's surface fields against a Σ; under the overlap discipline at most one candidate verifies, so it is the same function of (goal, scope), and the rejections are what the trace reports. (2) Derived globals are keyed by the goal type UP TO CONVERSION (a scanned Vec) and named by ordinal, not content-addressed: no component can encode a kernel type totally (Debug is budget-bounded by design, and a bounded key is a collision), so idempotence holds within an elaboration and cross-run/cross-module identity is residue. (3) Minting happens BETWEEN items, never mid-declaration — a global reference is GlobalVar(|Ψ|-1-abs+goal_base), so growing Ψ mid-item invalidates every reference already built — which means the FIRST use site of a derivation inlines its copy and every later one references the mint; the rollback-and-re-elaborate alternative was rejected as doubling every item that resolves something new. Only a PARAMETERIZED instance's result is canonicalized: a declared instance is already one global reached by name. (4) A `requires` binder's type is parsed as a class reference, because in front of a parameter list `Mag<A> (x: A)` reads as a value-parameter application. Layer 1's suite stays 31 green with the two edits its own §4.2/§8 predicted (a cross-member call now omits its requires; a generic instance's value is written bare) — the positional spellings became the negative controls. RESIDUE, owner = this issue: MODES (out-params) cut with evidence, not for time — construction checks a candidate against a fully zonked goal, and an output position that is still a meta has no goal to be checked against; making it real needs a nested resolution world plus a learn-only unification back into the caller's scratch world, its own slice. Nothing shipped in the meantime (no syntax that does nothing). Also residue: the agreement-proof escape for overlap (needs two values at one key, which the layer-1 name scheme cannot hold); content-addressed derived names (needs a total structural encoding of a kernel type; interacts with parallel-checking-and-caching); `let instance` as a keyword (the behavior exists for a plain `let`); receiver dispatch through instances (still layer 1 §8's); and trial cost (O(candidates) kernel checks per goal — file per the perf discipline if a corpus notices).
- 2026-08-07: 2026-08-07: Receiver dispatch through instances landed — layer 1 §8's residue entry and docs/traits-design.md §12's layer-1/2 ergonomics item, retired. Specification slice docs/traits-receiver-dispatch-design.md; ~150 lines in crates/elab/src/lib.rs (a class_members cheap-negative set, a class_dispatch step at the end of resolve_dot, a DotResolution::Dispatch variant carrying its own argument list) plus one loop in traits.rs. NO new resolution machinery, no kernel change: DISPATCH IS A RESOLUTION GOAL — the receiver's inferred kernel type goes straight to lower_instance to build C<typeof(x)> (the same call lower_named makes for a written C<T>, so an OPEN carrier needs no special case), layer 2's resolve_goal answers it, and the emitted term is the projection of the resolved dictionary applied with the receiver first. Neither guess in layer 1 §8 was taken: the concrete carrier is answered by the REGISTRY rather than by a member_head lookup of T::C::op, and the generic carrier by the scope search resolve_goal already had — which is why a carrier with no binder in scope but a derivable instance (Pair<Z,Z> via the generic Pair instance) dispatches for free, and why layer 2's scope-beats-registry order is inherited rather than re-decided. EMITTED-TERM CHOICE (slice §2.2): the projection, not the member global Rat::Monoid::op — it is the only form that exists for a local dictionary and for a derived instance, it is LITERALLY what the explicit spelling Rat::Monoid.op(x,y) elaborates to (so agreement is syntactic, not a conversion that happened to go through), and its type is the field's type at the carrier rather than the member's plus the instance telescope; the cost, that conversion δ-unfolds the instance value to reach the member's body, is the explicit spelling's cost too. AMBIGUITY RULES, all deterministic, no priorities, all pinned: (1) a field of the receiver's OWN type wins and dispatch is not attempted (surface-records §4.4 — that reading is the receiver's structure, so adding an instance reinterprets nothing); (2) an ordinary type-owned member, a bare name in scope, or a builtin beside a SUCCESSFUL dispatch is an error naming both, with both spellings — member_head's own growth-invariant rule extended, not a new one; (3) two classes with one member name both resolving at the carrier is an error naming both, every candidate tried even after one succeeds because the error is the point; (4) scope beats registry, pinned with a DISTINGUISHING local dictionary (its op returns the other argument) plus the negative control that the registry equation then fails; (5) a failed dispatch removes no reading — silent fallback when another reading exists, the layer-2 trace as the diagnosis when there is none; (6) candidates are exactly the classes a written reference would resolve to (key_of), so an unimported module's class captures nothing; (7) two narrowings refused by name — a bare x.op (no parentheses) never dispatches, and a multi-parameter class says so with the projection spelled. 17 tests in crates/elab/tests/traits_receiver.rs; layer-1 (31) and layer-2 (21) suites green UNEDITED; workspace 1231 -> 1248 full, lib/ir_v1.hthr untouched. THREE CORRECTIONS, slice §7 with evidence: (1) the planned 'carry the trace into the fallback and swap its error if that fails' was dropped — whether the call has another reading is decidable BEFORE the fallback runs, so dispatch either returns None or reports its search, and it reports it exactly where 'unbound name op' would have stood; no error rewriting, no judgment about which errors are swappable. (2) shadowed() cannot see the receiver-shaped BUILTINS — map/fold/head/tail/cons/cong/inj/absurd are Rust arms gated on !shadowed — so without naming them a class Mapper<A> { map: … } with an instance at the carrier would have SILENTLY captured xs.map(f), the one reinterpretation the growth invariant forbids; found by writing the test, now a named constant and a pinned ambiguity. (3) The receiver's type is inferred three times on the dispatch path (record branch, member_head, dispatch); recorded rather than fixed, since the cheap negative test bounds who pays and caching it is a resolve_dot refactor with its own regression surface. RESIDUE, owner = this issue: multi-parameter classes are not dispatchable (the goal would carry metas in the non-carrier positions, which layer 2 §4 declines to resolve — it wants the same nested-resolution world as modes and should land with it, not beside it); a class field has no self, so the receiver is always the field's first explicit argument and a member wanting the carrier elsewhere gets a type error rather than a message; a bare x.op never dispatches (surface-records §4.2's standing rule); two visible classes of one NAME disqualify each other silently, truthful but unhelpful; trial cost gains one multiplier on layer 2 §10's existing entry.

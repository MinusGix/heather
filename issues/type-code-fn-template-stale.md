Found by the 2026-09-15 design pass for [[parser-certified-composition-cost]] (docs/elaborator/telescoped-record-projections-design.md §2.1). `register_ty_code_fn` (crates/elab/src/gendefs.rs) computes the declaration's template in the current Ψ, pushes `D#tycode_fn`, then commits `TyCodeFn { template, stmt }` as computed; GlobalVars number from the end of Ψ, so from that push on every global in the stored template is one binding stale, and `instance_match` (§4.1's only route from an inline instantiation to its reference) fails its identity match for every declaration whose lowering mentions a global. On the parser reproducer the decline listing is dominated by `List` (762), `Or` (345), `Option` (45) against ~14 for the record rows; `Pair<A,B>`, `And<P,Q>`, `CollectionLiteral<A>(n)` match only because their lowerings mention no global. Fix shape: rescope on read off the reference's own variable (`shift_global(var.0 + 1)`), the discipline `rec_proj_ref_at` already documents; never shift at commit time (wrong after the next push). Image codec unchanged (byte 17 round-trips both types verbatim). Must land alone with its own before/after: the decline listing over lib/std loses its List/Or/Option rows, `scripts/bench --check` and the full `scripts/test` green with only this change in the tree, and the x86 rails re-measured, because it widens the type-code device across the whole library. Triggered by, and blocking, the device round on [[parser-certified-composition-cost]].

## Log

- 2026-09-15, implementation pass 1 (not landed; tree left dirty). **The stale frame is real and the rescoping is right, and it is half the defect.** `register_ty_code_fn` computes `template`/`stmt` with `psi.len == abs` and commits them after `push_gen_def`, so both are scoped in the prefix before their own binding; readers now take `ty_code_fn_at(tag, len_at)` / `ty_code_fn_now(tag, g)` (crates/elab/src/gendefs.rs), which shift by `len_at - abs` — the reference's own `var.0 + 1`, `rec_proj_ref_at`'s discipline — at `instance_match`, `gen_spine`, `unspell_here` and `unspell_ty_deep`. Nothing is shifted at commit time and the image codec is untouched. **What the shift alone does not fix:** a template global also carries the *telescope's* substitution tail (`u^{·^{|Θ|+d}}`) and `Holes::tm` compares a `GlobalTm` for syntactic equality, tail included, so the rescoped template matches only where the subject's context has the telescope's own length. Probe (`Slot<A>` = a record whose field mentions a global `ident`, crates/elab/src/wf.rs `mod stale_template`): with the fix the two sides agree on the global *index* (`u2` both) and differ only as `·^4` vs `·^3`; respell succeeds at the identity spine and still declines from a context of a different length. So the fix removes the **registration**-time declines and almost none of the use-site ones. Decline listing (new `HEATHER_GENDEF_DECLINES=1`, `value-metrics`) on `heather check -L lib/std -L lib/std/parser docs/showcase/calc_parser.hthr`, before → after: `register_rec_projs … binder-reference` 25 → 14 (`Decide` and `Failure` now register projections, `gendefs_pushed` 82 → 86; `CachedCursor`, `Cmp`, `Counted`, `Cursor`, `WholeGrammar` move to the dependency gate), `instance_match Cursor hole-match` 8957 → 6975, `Failure` 944 → 895, `Parser` 633 → 613 (+20 `unplaced-type-param`), `Decide` 58 → 49, `Certified` 368 → 365. **§2.1's attribution of the `List` (37 014), `Or` (570) and `Option` (195) rows to this defect is wrong** — those lowerings mention no global at all and their counts are byte-identical before and after; they are `tag_of`'s documented structural over-reach (`closed_type_ref`'s own note), the same thing that produces 365 157 `respell_ty_at False no-closed-code` rows. **The measured effect is a regression and the round stopped there** (release + `value-metrics`, `--kernel-workers 1`, one furnace box, before → after): whole file 137.8 s → 142.5 s wall, maxrss 4.94 GB → 4.88 GB, run total 137.4 s → 142.1 s, kernel gate 109.5 s → 114.9 s, conv misses 338 755 → 398 347, eval steps 13.0 M → 15.3 M. Head pairs rose where the brief said none may: `Wf/El(?)` 1374 → 46 159 (0.19 s → 2.52 s), `El(?)/Sigma` 89 → 14 455, `Sigma/El(?)` 432 → 1065, `Wf/Wf` 16 → 76. Attribution: this is `docs/elaborator/telescoped-record-projections-design.md` §2.4's own prediction — with `Cursor`/`Decide`/`Failure` named and `Certified`/`Success`/`Exists`/`ListElim` not, a reference meets an inline `Wf` at one side of the comparison; `calc_parser::number_grammar` 3.76 s → 4.99 s (14 770 → 41 498 misses) and `checked_expr` 2.87 s → 3.40 s (20 349 → 32 971) carry most of it. **And it is not merely slower — it is red.** `scripts/bench --check` against a `--save` taken on the parent tree on the same box is green (ok: 112 comparisons within thresholds), but the full `scripts/test` aborts on `crates/elab/tests/semantic_x86_warmup.rs::x86_semantic_prefix_is_ready`: the kernel rejects `lib/x86_64`'s `decode_mov_ri` with **`SubstMismatch`**, and the eleven `unbound name `decode_instruction`` lines after it are that one rejection cascading. Controlled back to back on one furnace box, same command, only these files swapped: parent `== suite: 1 passed, 0 failed ==`, changed `== suite: 0 passed, 1 failed ==`. `SubstMismatch` is a *local* substitution-tail disagreement, i.e. the same half named above arriving in an emitted term rather than in a decline: widening the device makes some site mint a reference whose tail does not match what the kernel expects. That is the first thing pass 2 has to explain, and the reason this must not land as it is. **Conclusion: §2.1 cannot land alone against a no-regression bar.** It needs the substitution-tail half of the matcher with it, and §2.2/§2.3 (the hidden value parameter and the type parameter in a term slot) to close the half-named set — which is the same "spell both sides alike or neither" §2.4 already states.

- 2026-09-15, implementation pass 2 (landed in the round's dirty tree; no commit). **The tail half found and fixed, and the `SubstMismatch` explained.** Pass 1's rescoping was right and was half the defect: a template global also carries the telescope's own substitution tail, and the reader compares a `GlobalTm` syntactically, tail included. Two edits in `crates/elab/src/gendefs.rs`: `Holes::tm` compares a **closed** global (empty `terms`, `Empty` tails) by its index alone, since the tail records the frame and nothing about the constant; and `instance_of_template` takes the **subject's frame** (`frame_tail(cx, d)`, or `spine_frame` off the spine head's own tail for the `unspell_here`/`unspell_ty_deep` inverse) instead of hard-coding `·^{|Θ|}`. The second is what pass 1 was missing in the *emitted* direction — with the index repaired and the tail not, `instance_of_template` produced a term whose local tails named a context of the telescope's length inside a frame of another, which is precisely a kernel `SubstMismatch`; `gen_spine`'s weakening of the closed statement moved off `shift_local` for the same reason (it keeps the stored `·` base where the frame may end in a context variable). With these, `crates/elab/tests/semantic_x86_warmup.rs::x86_semantic_prefix_is_ready` is green inside the full suite and the x86 rails are unmoved. **Pass 1's correction stands**: the `List`/`Or`/`Option` decline rows are `tag_of` structural over-reach, not this defect — the listing now says so in its own words (`hole-match-Wf/Sigma`, `hole-match-Sum/Sigma`: the template is the whole `Wf`/`Sum` and the subject is a component of it). **What the rescoping still does not reach**, now named by the listing rather than guessed: `hole-match-type-hole/two-occurrences-disagree` (the subject spells one closed type argument two ways — a binder's type is a structural read and stays inline, an application's type argument went through the emission chokepoint and is a reference) and `hole-match-Wf/El` (the stored template is inline by construction and a subject that arrives already emitted carries a reference at the same node). Neither is fixable in the matcher: step 2 requires the template at the recovered arguments to be the subject *syntactically*, so no choice of argument satisfies a subject that contains both spellings. On `docs/showcase/calc_parser.hthr` that leaves `Cursor` 926 + 618, `Certified` 196 + 134 + 72, `Failure` 105 + 53, and about 350 `project_field … instance-args` field reads on the inline walk. Follow-up slice: `docs/elaborator/telescoped-record-projections-design.md` §2.3 as amended — spell a declaration's type arguments and its binders' types alike. Measurements for the round on [[parser-certified-composition-cost]].

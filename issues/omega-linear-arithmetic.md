Extend the checking-only `arith` form from additive equality normalization to
a certifying solver for quantifier-free linear arithmetic over `Nat` and
`Int`. The implementation belongs in the Rust elaborator. It is untrusted:
success reconstructs an ordinary Heather proof term and the enclosing
declaration's ordinary kernel gate remains the authority.

The first solver deliberately follows the implemented fragment of Lean 4's
`omega`, not the completeness claim of full Presburger arithmetic. It solves
equalities first and then runs exact-preferred Fourier--Motzkin elimination
(the Omega algorithm's real shadow). Dark and grey shadows are a later
completeness extension. A surviving real-shadow problem is therefore a
structured `NoContradiction` result, never a satisfiability verdict.

## Target scope

Recognize hypotheses and goals built from:

- `Nat` and `Int` equality, `<=`, and `<`, plus their negations;
- integer negation and subtraction;
- addition and multiplication by a closed numeral;
- conjunctions and lazily split disjunctions;
- arbitrary opaque atoms for nonlinear or otherwise unrecognized terms.

Embed natural expressions in integer arithmetic and add non-negativity facts
for natural atoms. Do not unfold opaque powers or nonlinear products merely
because they occur in an arithmetic goal.

The core representation is a signed linear combination
`constant + sum(coeff[i] * atom[i])` and an interval constraint on a
coefficient vector. Constraint insertion canonicalizes sign and, in the pure
search API, GCD; rounds integer bounds in the sound direction; intersects
duplicate vectors; records tight bounds as equalities; and detects crossed
bounds as contradictions. The certificate frontend currently disables GCD
reduction: that preserves sound search and the real-shadow fragment while
avoiding an unreconstructable floor/ceiling step until
[[omega-div-mod-expansion]] supplies the required quotient laws.

Equality processing first eliminates a variable with coefficient `+1` or
`-1`. Hard equalities use Lean's balanced-remainder transformation and a fresh
auxiliary integer before ordinary elimination. Inequality processing chooses
an exact elimination when possible, otherwise minimizes the number of
lower/upper pairs generated by Fourier--Motzkin.

## Proof architecture

Do not eagerly build source strings or a recursive proof tree while solving.
Every initial and derived fact points into an append-only derivation DAG whose
node kinds correspond to assumption, normalization, bound intersection,
linear combination, and balanced remainder. Once a contradiction is found:

1. mark only nodes reachable from it;
2. topologically order those nodes;
3. emit shared intermediate proofs as generated `let` bindings;
4. elaborate the completed ordinary expression and pass the enclosing
   declaration's kernel gate.

This intentionally improves on Lean's currently tree-shaped justification
extraction. Certificate sharing is part of correctness-at-scale, not a later
pretty-printing optimization: the existing additive reconstructor has already
measured reassociation and transitivity-tree shape as its dominant cost.

Every run extends the existing audit interface with atom/constraint counts,
normalization and elimination counts, disjunction splits, reachable versus
discarded derivation nodes, exact used-lemma set, and a stable residual problem
when stuck. Arithmetic overflow is a structured refusal and must never wrap.

## Acceptance

- Prove representative open `Nat` and `Int` consequences using multiple local
  hypotheses, including equality substitution and upper/lower-bound
  contradiction.
- Prove at least one problem requiring non-unit coefficients and one requiring
  a non-exact real-shadow step whose real relaxation is contradictory.
- Refuse a satisfiable mutation and an unsupported problem with stable residual
  constraints; never label either one `satisfiable`.
- Treat nonlinear terms as opaque atoms and never reduce an open or large
  power to classify it.
- Differential-test the pure Rust solver against bounded exhaustive models on
  generated small linear systems. A solver success must have no model.
- Kernel-gate every positive end to end, pin the used lemma set, require zero
  value-cache eviction, and record certificate growth on a scaling family.
- Keep the current additive and bounded-Boolean `arith` customers green.

## Explicitly deferred

- dark and grey shadows, and hence completeness for Presburger arithmetic;
- division, modulus, and divisibility ([[omega-div-mod-expansion]]);
- `Nat` subtraction, `min`/`max`, `Fin`, and `BitVec` frontend conveniences;
- an in-Heather reflected checker or an in-Heather solver implementation;
- general `grind` orchestration ([[grind-port]]).

## What it assumes from elsewhere

- **[[certifying-arithmetic-proof-automation]]** owns the `arith` checking
  form, its trust boundary, and the existing additive/Boolean customers.
  Assumed here: only that a new deterministic solver may return an ordinary
  certificate and extend the same structured report.
- **[[arith-compact-additive-certificates]]** owns compact certificates for
  the old AC normalizer. This issue does not silently replace that fragment;
  it invokes Omega only after the cheap specialized closers fail.
- **[[grind-port]]** owns eventual multi-solver orchestration. Assumed here:
  only that Omega's structured stuck state can later be embedded in it.

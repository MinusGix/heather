What a `runtime fn` of a laid record does not take yet (docs/native/layout-design.md §9.5, round 3; probes in `lib/_tests/native/runtime/runtime_held_tests.hthr` and its neighbours). Each is refused by name unless noted.

- **A branch that is not the function's last statement, with a store in an arm.** It elaborates to a branch inside `Mutated`, which the reflector refuses ("write the branch around the whole result, each arm its own end"). A tail `if`/`else` works.
- **A call of a function of the record that only reads it** (`self t: T`, answering a word alone). A call of one that takes `mut self` works (probes in `runtime_held_call_tests.hthr`); the term of a reader's call is the call itself, a value among values, and the walk makes calls only where it finds them under `.after` and `.value`. Give the callee `mut self` meanwhile.
- **An array field written out anew after a call of another function of the record** (`t.f := [a, b, …]` after `t.m(x)`). The entries that changed are told from the field's own by comparison with the record's local, which after a call is no longer the record. An element stored with `vector_update`, at a word or at a numeral, works after a call.
- **A read of the record as it was before a call, first met under a `match` that is a value.** Before each call the walk reads what the body uses of the record afterwards (`let old = t.count; t.bump(x); old` works), and it does not look under the arms of a `match` in a value.
- **A record a function left behind, built on again**: `Mutated(t, m.value)` after `let m = Tally::bump(t, x)`, or a call handed the record as it was two calls ago. The span holds one record.
- **A loop that is not a `mut self` method ending in its own call.** A loop is taken (probes in `runtime_held_loop_tests.hthr`): it `decreases` a 64-bit word's `toNat` and ends, in a tail `if h:`, in its own call. Not taken: a loop that only reads the record (give it `mut self`), a self-call whose word is used afterwards, and a loop whose ending arm stores into the record, which has no `ext` companion ([[decreases-no-companions-ending-arm-store]]; store before the test, or in a caller).
- **A function over a bare span that calls a function of a record learns nothing of the record.** `let ran = T::m::bytes(ctx, cn, …); ctx := ran.after; ran.value` compiles (`List::tally_take`, `runtime_held_span_tests.hthr`), and the call must be bound that way: a span function may not end in the call itself. Its instance states bytes; what the span then holds is the callee's `runs_held` to cite.
- **Operands and results that are not 64-bit words.** A `u32` result, a `Nat` operand, a `Bool`.
- **A field whose codec has no accessor** (a `u16`, a `u8`, an array of them): it can sit in the record, and a function that neither reads nor changes it compiles.
- **An element at a word index of an array whose elements' codec has no checked accessor, or by a proof.** An array of big-endian 32-bit or 64-bit words is read and stored at an index that is a word (`vector_get(t.f, i.toNat(), 0)`, `t.f := vector_update(t.f, i.toNat(), x)`; probes in `runtime_held_index_tests.hthr`), and at literal indexes as before. The element is the total one: the code tests the index against the count, reads 0 past it and stores nothing. Not taken: `vector_index(t.f, i.toNat(), inside)` with a proof (it would save the comparison), a pad that is not 0, `vector_get` at a literal (write `vector_index`), and a field whose new value mixes `vector_update` at a word with one at a literal.
- **The index spelled `t.f[i]`.** `v[i]` is the kernel's `nth` at a `Fin`, which the host's `View` shows no layer of, so the reflector answers "a form the reflected fragment does not have". It is `vector_index(v, i, trivial)` by `refl`. Either the view presents it or the reflector asks whether the term is an entry; and `t.f[i] := w` is not a place yet (a parser lowering to `t.f := vector_update(t.f, i, w)`). Both are surface: at a word the index would read `vector_get(t.f, i.toNat(), 0)`, which is built, and whether `t.f[i]` at a word means that total read is Minus's to choose.
- **A byte of a word array, beyond a store into big-endian 32-bit words at a word index.** `t.f := vector_with_byte_be(t.f, i.toNat(), b.truncate(8, 56))` compiles to one checked byte store (`List::put_byte_at_within`; probes `Sums::tag` in `runtime_held_index_tests.hthr`, `Sha256::put`). Not taken: the byte at a numeral index (refused by name), an array of 64-bit or little-endian words (the lemma `Stored::u32_be_put_with_byte` is stated at one codec, not at the `Accessor` class), and a byte read (`vector_get` of the word and a shift does it meanwhile).
- **A span that is read, beyond its bytes one at a time and its passing on.** A function of a record takes the spans it only reads after the record, each a `List<u8>` and its length word, before its words (`runtime_held_span_tests.hthr`); a byte is `src.byte_within(sn, i)`, and a callee or the loop's next pass is handed the span as it came, in its own place. Not taken: a span after a word, a span passed in another's place or a window of one (`src.window(…)`), a span handed to a function that only reads (a pure `runtime fn` lent it), a second span that is written, and a loop whose measure mentions the span's bytes (its `ext` is read at the file's span whatever the recursion is handed, which needs the bound's type not to name the span).
- **A field read before a call and used after it.** `let c = s.count; s.pad(…); … c …` does not pin: the read is reflected where it is used, after the call's stores, and the comparison does not see that the callee leaves the field. Passed as a parameter it compiles (`Sha256::close`).
- **What a loop's code does at a span that holds no record** is not stated: its function over the bytes is its body iterated as often as the code counts, at every span, and only where the span holds a record is that the function of the record.
- A function that changes nothing is compiled as a function that writes its span (it stores nothing). Its code is right and it is marked as one that may leave the file changed, so a caller cannot yet learn the file is still from the mark.
- The refusal for a record that is not laid says "`Plain` has no runtime layout under the reflected fragment". It could say `laid record`.
- The generator's run is long for a long function: it grows with the square of the statements (each statement's reads go through every earlier store when the lowering is checked), outside the kernel as much as in it.

Found on the way and fixed in the same round: `laid record` stopped at fourteen fields (what it published grew with the cube of the fields and passed what the host reads of one reply; it now holds each shared term once), and the elaborator's reduction request walked a record updated field by field as a tree (fields to the power of updates; `contract_projections` now visits a shared node once).

## Log

- 2026-11-12: Measured 2026-11-12: under the test profile's binary (the one the whole-library gate runs) the generator takes far longer than under the release binary on the same function, by a factor of tens (a nine-statement function a few seconds against most of a minute; a function of nine read-and-store statements past three minutes, which with the rest of its test file passed the gate's per-module CPU rail). The probes keep `State::init` and drop the longer cases for that reason. Where the factor comes from has not been looked at.
- 2026-11-12: 2026-11-12, PR #551: array fields, at literal indexes. A record function reads `vector_index(t.f, i, trivial)` and stores the entries of a field's new value that changed, each by the element codec's accessor where the element's part lies; the marks name only the elements the function reaches. compile-x86 exports a record function as its function over the span. `Sha256::init` is the first function of the context record that is linked (`sha256_init` is its code).
- 2026-11-12: PR #551: a function of a laid record calls another (`t.m(x)` at a `runtime fn T::m(mut self …)`): the callee's code over the span is called, the caller's theorem is read off the callee's `runs_held`, and a caller of a caller links. Probes `lib/_tests/native/runtime/runtime_held_call_tests.hthr`. The bullet for it is replaced by what the call does not take (a callee that only reads, an array field changed after a call, a read first met under a value's `match`, a record left behind, a span function calling a record function).
- 2026-11-13: PR #551: a loop in a function of a laid record. A `mut self` method that `decreases` a word's `toNat` and ends in its own call compiles; its function over the bytes is its body iterated the passes the code counts (`FFun::rounds`, no floor in the class), and `runs_held` is proved from the function's own equation at records (`rt_held_loop.hthr`). A loop calls other functions of the record and is called by them. Probes `lib/_tests/native/runtime/runtime_held_loop_tests.hthr`. Not taken: a loop that only reads, a self-call that is not the end, an ending arm that stores (decreases-no-companions-ending-arm-store).
- 2026-11-13: PR #551: an array element at an index that is a word. `vector_get(t.f, i.toNat(), 0)` and `t.f := vector_update(t.f, i.toNat(), x)` compile at an array of big-endian 32-bit or 64-bit words, by the codec's checked element accessor (`Accessor`'s `read_at`/`write_at`), which tests the index against the array's count: the element is the total one, with no bound to prove. Two more marks in `rt_held.hthr` (`Indexes`, `Stores`) and one lemma per direction for every array (`Stored::held_index`, `Stored::held_store`). A loop over an array compiles and runs on bytes (`Sched::expand`, the shape of the message schedule). Probes `lib/_tests/native/runtime/runtime_held_index_tests.hthr`.
- 2026-11-13: PR #551: SHA-256's compression as methods of `Sha256` (`lib/native/crypto/sha256_compression.hthr`). Two limits went with it. An element stored at a numeral after a call (`vector_update(t.f, 0, x)` after `t.m(…)`) is the accessor's own store. And a function calling loops of its record at numerals pins: the pin is proved with the callees parameters (`revert_into` at a global), where at the callees the comparison unfolded each loop before the sides met and `Sha256::run` ran past the budget. Probes: `Sums::seal` (`runtime_held_index_tests.hthr`), `Tally::thrice` (`runtime_held_loop_tests.hthr`), `sha256_compression_tests.hthr`.
- 2026-11-13: PR #551: what a caller costs to elaborate. A function of a record that calls another carries its callee's whole program in its own generation, and the cost climbed with the depth of the chain: under the test profile's binary `set` (calls `shift`) took about a tenth of the library gate's per-module rail, `turn` (calls `set`) a third and a `step` that called `turn` nearly all of it, with the kernel's share of each under a second. A loop's generation does not climb that way. So the round is flat (`Sha256::rounds` calls `Sha256::t1` and `Sha256::turn`) and the methods are three modules ([[runtime-tests-cold-build-past-rail]]). One cause was in the host and is fixed (`Run::sigma` copied every hole's solution at each application of a generator's expression); what is left is the generator's own work per callee, not looked into. Also: the pin is tried at the callees first and at parameters where that runs out, because a function whose record after a call is built whole from that call's word (`Tally::reset`) pins at the callees and not at parameters, for a reason not found.
- 2026-11-13: PR #551: a function over a bare span calls a record function's code. `T::m::bytes(span, length, …)` is a callee the span reflector takes when the callee is a record function's (`rt_record_of`, `rt_file_reflect.hthr`); SHA-256's linked compression is `Sha256::run` that way. Two limits of it. The call must be bound and its span stored back (`let ran = T::m::bytes(ctx, cn); ctx := ran.after; ran.value`): a span function may not end in the call itself ("a function over a span ends in `Mutated(span, value)`…"). And the span function learns nothing of the record: `runs_held` is the callee's theorem, and a span function's instance states only bytes, so a caller that wants `Sha256::run` of the context it holds cites `Sha256::run_holds` itself.
- 2026-11-13: PR #551: a byte of an array of big-endian 32-bit words is one store. `vector_with_byte_be(v, i, b)` (`stored_words.hthr`) is the array with byte `i mod 4` of word `i div 4` replaced, and a record function that assigns it to the field at a word index compiles to `List::put_byte_at_within`, a byte at `base + i` under `i < 4 * count`. It rides the word store's mark (`Writer::Stores`), with its own entry per array (`Part::byte_entry`, `HWorld::stores_bytes_array`), and its soundness is the word store's by `Stored::u32_be_put_with_byte`. `Sha256::put` is that one statement, where it was a word read, a four-way branch and a word stored.
- 2026-11-13: PR #551: a function of a laid record reads a second span. `T::m(mut self t: T, src: List<u8>, sn: u64, …)` compiles: the code takes the record's span and then the read span's place and length word, and `T::m::runs_held(own, t, length, src, sn, …, holds)` is the agreement of `T::m::bytes(own, length, src, sn, …)` with `T::m(t, src, sn, …)`. The theory needed nothing new (`FTm::held` was already at any rest of a file); the generator's marks, what they owe and a loop's equation became functions of the rest of the file, read at the function's own spans in the theorem. A loop's `ext` compares recursions at every span, and the body hands on the one it was given, so each recursion compared is read at the file's span. Callers and loops that call work (`Tally::both`, `Tally::each`). With it every function of the linked SHA-256 is a method of `Sha256` (`sha256_stream.hthr`): `absorb`, `take`, `update`, `finish`, `take_block`, `compress`; the bullet for a span function calling a record function is dropped, the stream no longer being written that way.
- 2026-11-13: Minus ruled (2026-11-13) that an element at a word index requires a proof, found implicitly: junk values are a sign of not enough automation. The checked total element is to be replaced. What stands in the way is not in the record functions: [[if-evidence-hidden-from-tactics]] and [[found-proof-differs-across-recursion-companions]]. With those, `vector_at`/`vector_put`/`vector_put_byte_be` (each with `inside := bv_omega`) reflect as the reads and stores do today (tried: a loop over four words and a tested store compile). Still to design: a proof as a parameter of a function of a record, which needs the callee's meaning to be stated without the proof; and a branch on an equation as the value of a function that only reads the record, which does not pin.
- 2026-11-13: PR #607: an element at a word index takes a proof that is found (`t.f.at(i)`, `t.f.put(i, x)`, `t.f.put_byte_be(i, b)`, the `Vec` methods of `stored_words.hthr`; `inside: i.toNat() < n := bv_omega`). `vector_get(…, 0)` and `vector_update` at a word's `toNat()` are refused in a function of a record with the form to write. The code still makes the accessor's compare. Limits this leaves: (1) a callee cannot take a proof (a caller's meaning names its callee as a total function of record and words), so an index bounded by an invariant is tested where it is used (`Sha256::put`'s `if h: at < 64`) or read in the loop and passed as a word (`Sha256::t1`'s `w`); (2) a tested read as the value of a function that stores nothing is refused ("a branch on an equation" is not written out as a value; probe `Sums::part`), so such a function stores what it reads or is `mut self` with a statement; (3) `bv_omega` does not know `(x & 15).toNat() < 16`; (4) dropping the compare needs each site's bound carried to the accessor's unchecked law, the same theory as (1).

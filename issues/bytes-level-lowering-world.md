Item 7 of [[bytes-level-lowering]]: the world. The `Sys` node's step lemma for `read` and `write` (for every answer and resumption the Linux model allows; a failed read leaves its window undefined, which `Injected::undefined_change` absorbs), `Exit`, and the going and exited clauses of `Site::Meets` (`lib/std/arch/x86_64/x86_64_call_contract.hthr`). `EmitsBy` is a claim about machine steps (`Site::Moves`); a system call needs the claim form `Site::Performs`, so a region holding one is proved in that form, the regions without one lifted into it.

## Done when

`Site::Meets` in all three clauses for every routine of every program the lowering returns; the language's world probes (`echo_*`, `failed_read_undefines`, `exits`) compiled with their theorems.

## What it assumes from elsewhere

- **[[bytes-level-lowering-routines]]** owns the done clause. Assumed: it is proved for programs without system calls.

  1. **The system call is blocked at the generic theorems, not here.** A `Sys` node's step is a claim in `Site::Performs` form (steps to a SYSCALL that `LinuxRequests` reads, then from every resumption `LinuxResumes` allows). By the round's rule this is a generalisation at their source (`function_ir_lower_calls`, `x86_64_stack_runs`): e.g. `EmitsBy` over a claim form `site.Claims(writes, from, to, pre, post)` that is `Moves` or `Performs`, with `moves_trans`'s analogue for `Performs` (a run to a call, then from every resumption, a run again). Not started; the coordinator's call.
  2. **The `Sys` node itself**: code (the number in RAX, the descriptor, the window's address and the count in RDI, RSI, RDX, SYSCALL, the answer from RAX), its step lemma for every answer and resumption the Linux model allows (RCX and R11 clobbered; a failed read's junk absorbed by `Injected::undefined_change` and `Piece::undefined`), and the bridge from `SysCall::run` to its facts at the valuation (the scope check: a `Sys` binds its `result` word).
  3. **The going clause, even without system calls.** `Site::MeetsGoing` is a statement about every `Running` reachable by `Site::Step` before the return, including on runs that never return (a loop at every fuel `Going`). Every theorem so far is existential (a run reaches the post). It needs an invariant over all reachable states: for code with no SYSCALL, that every reachable state before the return is on the code's run, so no system call is made and the world stays `io` (whose history the meaning reaches at fuel 0, `Going(io)`). That wants the machine's determinism (`Site::Step` over a fetched step) and the code's control staying within its labels, which the region theorems do not state. With system calls, each reachable world must also be matched to the meaning's history at some fuel, by the same induction as the done clause.

- 2026-11-25: Note for the next round's design (the coordinator's six questions; nothing built).

  1. **How fuel is spent.** Per call and per pass, along nesting, not along time. `program_calls(Succ(rest))` answers a call with the callee's body at `rest` and the body's own calls by `program_calls(rest)`; `Seq` and `Branch` run both parts at the same fuel; a `Call` is answered by the routine's `calls`, unchanged inside a loop; `loop_run(Succ(rest))` runs a pass's body at `rest` and the next pass at `rest`. So a nested loop in a pass starts at the outer loop's remaining fuel minus one, but a call inside a pass is answered at the routine's call fuel, not reduced by the passes before it. `Going` arises only from `program_calls(0)` or `loop_run(0)`. **True statement:** `run` `Going` at `n` implies a chain of at least `n` events, each a call entry or the start of a pass, each nested inside the one before or, for passes of one loop, following it (the run at `n` itself counting as the first call). **Not true as stated for machine steps counted only at the turn and the CALL:** a pass's start costs a turn's JMP H only from the second pass on; the first pass starts after the loop's entry moves, which can be empty (inputs already in the state's registers, `File::plain_entry`), so a chain of nested loops entered at their first pass reaches `Going` with as few as `n` minus the nesting depth counted steps. Fixes: count the loop's head arrival (the lowering can make the entry non-empty, or the claim can count pass starts as a ghost), or let the meaning charge a loop's first pass to its entry. Every pass does run its exit test (`TEST`/`CMP` and `Jcc`, `plain_done`) before turning or leaving, so passes that complete cost at least two steps each.
  2. **Determinism.** Yes, as modelled, up to the state's defined components: `step_respects_defined` (`x86_64_step_forms`: two `MachineStep`s from `SameDefinedState` states end `SameDefinedState`), and `syscall_excludes_step` (no `MachineStep` where SYSCALL is fetched). `linux_steps_meet`/`linux_steps_peel` (`linux_x86_64_determinism`) compose them over runs between syscalls, and `linux_runs_determine` is the whole-run form. `Site::Step` is `MachineStep` or the Linux answer, so a determinism lemma for it is a few lines over these; the resumption is a choice (`junk`, RCX, R11) that the claim already quantifies over.
  3. **What `Sim` needs.** `RunsAs` (`linux_x86_64_sim`) is `CallSystem::Holds` of a trace: from the state, silent `LinuxStep`s to a stop that asks the trace's call, and from every resumption Linux allows the rest; `TEnd` is `True`, `TRet` an exit. `Site::Performs` is that shape, so a fuel-indexed `Tracks` gives `RunsAs` of the meaning's history at each fuel (`Going(o)` read as the trace of `o.past` ending `TEnd`, `Exited` ending `TRet`) with no universal over reachable states; `Sim` at every fuel (`SimProgram`) follows. The existing statement does **not** constrain a machine that makes a system call where the specification diverges silently: at a cut a tree has only the empty trace, and the module says so ("a tree that is cut at every fuel along a run ... is simulated by a machine that goes on and exits"; `LinuxSimCo`, `issues/linux-sim-divergence.md`). `Tracks` with "after at least `n` steps" at `Going` plus determinism would be stronger than `Sim`.
  4. **`Moves` that `Performs` cannot replace mechanically.** Composition is mechanical once the contract has a bind for `Performs` (from every goal state, `Performs` again; counts add): `moves_trans`, `may_emit_by_seq`, `branch_emits_by` (`moves_test_by` branches at one state), `Site::loop_iterates`, `function_runs_by`'s stages. Goals that mention another state are fine as goals parameterised by it (`call_step_by`'s `leaves` over `u` and `t`; `Site::Returns`' `post(i, s, t)`; `EmitsBy`'s `s0`). `function_runs_by` uses `body_emits` twice from one state family, but the second use is only its `Within` half. **Not mechanical:** (a) the memory clause's one law, `Stack::ClauseStable`, is stability under the frame's own stores; a system call writes the read's window and leaves junk, so `TrailBy` (`WroteIn` and `Mem`) needs a law for the kernel's write (inside the lent spans, `Injected` after the read's put, `Injected::undefined_change` for junk); (b) `Site::Moves`' end conclusions `t.rip`, `site.Resident(t.memory)` must survive the kernel's write (the window apart from the code: the `Loan`'s placement has it, but no generic theorem states it); (c) `Site::Returns`, the callee contract `call_step_by` takes, is itself a single run (∃ `t`, `MachineSteps`), so a callee that makes system calls needs `Returns` restated in claim form, and `Site::moves_call` with it.
  5. **Recursion.** FunctionIR: `Function.levels`; the meaning is truncated at that depth (`Function::effects_at`, `tied_effects`); the room is static, `level_room(0, frame + 24, levels) <= rooms(k)` (`Function::roomy_levels`, `self_rooms`, `Function::emit_levels_self`). The gate (`native_recursion.rs`): `sum(10)` non-tail recursive exits 55 within 16 levels; with 9 levels the tenth nested call exits 139 at run time (the program compiler's too-deep exit); a generated `runtime fn` recursion at its inferred eleven levels and one short at ten; a 64 KiB stack budget accepted, 64 bytes refused. I would index the room by the run's peak call depth: define it by `run`'s own recursion (`run` unchanged), and `Site::Entering`'s premise `room(f, peak) <= i` with `room` a table by routine and depth; acyclic programs have a table constant past their height, today's `routine_rooms`, so one statement. A depth passed down by the caller needs the same peak to state when the clause applies, so it is that with the depth as a parameter. The gate's run-time refusal (exit 139) is a meaning the bytes level does not have: an out-of-stack outcome or the guard in the routine's meaning. Filed: `issues/bytes-level-lowering-recursion.md`.
  6. **Awkward in `Site::Entering`/`Site::Returned`.** The lending law is not in it: the done theorem takes `Loan` and `blocks.Lent(spans)` beside `MeetsDone` (the language's writable blocks against the spans is a premise outside the contract). `io.Answerable()` is unused by the done and exited clauses. `Site::Returned`'s `ArgsIn` over nine registers is false for more words, so a routine answering more is refused by the lowering rather than by the contract. The room `rooms(f) <= i` is per routine and per fuel-independent, which is what made recursion unstatable (5). Nothing else was in the way.

What the second experiment ([[ownership-checker-call-and-write-view]], `lib/lang/ownership/call_check.hthr`) did not test of the checker, from its log of 2026-11-25: the rest of package 3 of `docs/language/ownership-design.md` §16 (calls, write views, regions, joins), at the level of the checker and its meaning. Library only, over that module's world-of-callees structure. The bytes level, references stored in memory down to x86, is [[ownership-reference-cells-spike]], which §16 calls the third experiment; this issue does not touch it.

## Scope

- **Stored references and the erased owner** (§15.2, §15.5): a `&mut{o} T` held as a value in a cell, so the run's file holds references; a callee that consumes a collection of them takes an erased in-out owner. `FnSafe`'s frame must then cover what is reachable through stored references, and the meaning's slot is the path it returns to.
- **A branch with a join** (§15.3): two arms whose place states differ (a view dead on one arm, a version bound on the other); the join is the meet, with regions coarsened; residuals under the branch's condition.
- **A loan held across statements**: `let w = &mut x[lo..lo+n]`, writes through `w`, then its death. The second experiment's loan lasts one statement (`CallMut`), so no window is ever `out` between statements and `Sim.on` never needed weakening; this is where "the buffer holds the holder's value outside its out windows, and each out window holds its viewer's value" is first an invariant rather than a step's two premises (`written_back`).
- **A finer returned region**: a signature that places a returned view in a window of its parameter, so the caller may write apart from it. There `FnSafe.view_in` becomes load-bearing for a frame; in the second experiment it is used only to place the view inside the whole object it freezes.

## What it assumes from elsewhere

- **[[ownership-fnsafe-postconditions]]** owns facts about a callee's answer. Assumed here: nothing; a branch on a callee's answer would want it.
- **[[place-check-name-lookup-cost]]** owns the closed verdict's cost. Assumed here: several objects bring back a holder table, which should be a map keyed by buffer.

## Done when

`check_sound` over the extended fragment, one accepted program per addition and a `¬` control for each refusal, and the log answers whether the place states still suffice once references are stored (the condition under which §15's design says a separation algebra might be needed: placement, not the checker).

## Log

- 2026-11-25: Item 1, a loan held across statements: built and proved. `lib/lang/ownership/call_check.hthr` is restructured, deliberately, so one checker covers the second experiment's calls and the loan: no second module. The write parameter is a place (`Set(i, v)` is `x := x.set(i, v)`; the per-object version counter `top` is gone, since with one object it only counted writes, and a join could not meet two arms that wrote different numbers of times). `View(t, md, lo, n)` opens a view to read or to write; `Put(t, i, v)` writes through a live write view; `CallMut(g, t, args, z)` lends a live write view to a callee for the call; the second experiment's `CallMut(g, x, lo, n, args, y, z)` is `View(t, Writes, lo, n); CallMut(g, t, args, z); Die(t)`. In the meaning (`Sem`: the place's value, each view's value, each view's slot, the words) a write view is its value and an erased slot, and `Put`/`CallMut` write it back at once (`Sem::back`: `cur.put_window(slot, nv)`), §15.2's eager write-back. The checker's state is the live views with mode and region; an access to write needs every live view apart, an access to read every live write view (`LView::meets`, `license_live`).

  Proved: `check_sound` and `prog_sound` as before, over the new fragment.   Refuting conditions for this item. *Is the weakened invariant enough, or is something else needed?* Neither: the invariant does not weaken. With eager write-back the file holds the holder's value inside an out window too, because the holder's value there *is* the viewer's. What a live write view adds is its own hold (`Lent`: its reference is `narrow(r, slot, n)` for the meaning's slot, it holds its value there) and exclusivity (`Sim.excl`: a live write view is apart from every other live view, which is what `out(viewer)` means). No separation algebra, history or ghost state: `excl` is a fact about the live views' references, maintained at each new view from the licence. *Does eager write-back cost something that grows with the loan's length?* No: each `Put` and `CallMut` is one `Sim::backed`, whose write-back is the same `written_back` the second experiment proved for a call; the proof is once, and a program pays nothing per statement of the loan beyond the checker's scan of live views. Kernel cost of the proof: the module elaborates in about 20 s on a fresh cache; the dearest declarations are the window lemmas (`narrow_window` 1.7M steps, `written_back` 1.4M), not the loan. `step_view` stated inline cost 6.6M steps and 24 s; split into `Sim::view_core`, `narrow_within`, `clear_apart` it is 40k.

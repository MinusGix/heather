What the second experiment ([[ownership-checker-call-and-write-view]], `lib/lang/ownership/call_check.hthr`) did not test of the checker, from its log of 2026-11-25: the rest of package 3 of `docs/language/ownership-design.md` §16 (calls, write views, regions, joins), at the level of the checker and its meaning. Library only, over that module's world-of-callees structure. The bytes level, references stored in memory down to x86, is [[ownership-reference-cells-spike]], which §16 calls the third experiment; this issue does not touch it.

## Scope

- **Stored references and the erased owner** (§15.2, §15.5): a `&mut{o} T` held as a value in a cell, so the run's file holds references; a callee that consumes a collection of them takes an erased in-out owner. `FnSafe`'s frame must then cover what is reachable through stored references, and the meaning's slot is the path it returns to.
- **A branch with a join** (§15.3): two arms whose place states differ (a view dead on one arm, a version bound on the other); the join is the meet, with regions coarsened; residuals under the branch's condition.
- **A loan held across statements**: `let w = &mut x[lo..lo+n]`, writes through `w`, then its death. The second experiment's loan lasts one statement (`CallMut`), so no window is ever `out` between statements and `Sim.on` never needed weakening; this is where "the buffer holds the holder's value outside its out windows, and each out window holds its viewer's value" is first an invariant rather than a step's two premises (`written_back`).
- **A finer returned region**: a signature that places a returned view in a window of its parameter, so the caller may write apart from it. There `FnSafe.view_in` becomes load-bearing for a frame; in the second experiment it is used only to place the view inside the whole object it freezes.

## What it assumes from elsewhere

- **[[ownership-fnsafe-postconditions]]** owns facts about a callee's answer. Assumed here: nothing; a branch on a callee's answer would want it.
- **[[place-check-name-lookup-cost]]** owns the closed verdict's cost. Assumed here: several objects bring back a holder table, which should be a map keyed by buffer.

## Done when

`check_sound` over the extended fragment, one accepted program per addition and a `¬` control for each refusal, and the log answers whether the place states still suffice once references are stored (the condition under which §15's design says a separation algebra might be needed: placement, not the checker).

- 2026-11-25: Item 1, a loan held across statements: built and proved. `lib/lang/ownership/call_check.hthr` is restructured, deliberately, so one checker covers the second experiment's calls and the loan: no second module.   Refuting conditions for this item. *Is the weakened invariant enough, or is something else needed?* Neither: the invariant does not weaken. With eager write-back the file holds the holder's value inside an out window too, because the holder's value there *is* the viewer's. What a live write view adds is its own hold (`Lent`: its reference is `narrow(r, slot, n)` for the meaning's slot, it holds its value there) and exclusivity (`Sim.excl`: a live write view is apart from every other live view, which is what `out(viewer)` means). No separation algebra, history or ghost state: `excl` is a fact about the live views' references, maintained at each new view from the licence. *Does eager write-back cost something that grows with the loan's length?* No: each `Put` and `CallMut` is one `Sim::backed`, whose write-back is the same `written_back` the second experiment proved for a call; the proof is once, and a program pays nothing per statement of the loan beyond the checker's scan of live views. Kernel cost of the proof: the module elaborates in about 20 s on a fresh cache; the dearest declarations are the window lemmas (`narrow_window` 1.7M steps, `written_back` 1.4M), not the loan. `step_view` stated inline cost 6.6M steps and 24 s; split into `Sim::view_core`, `narrow_within`, `clear_apart` it is 40k.
- 2026-11-25: Item 2, a branch with a join: built and proved. A body is now a tree, `Body = End | Do(stmt, rest) | If(Cond, a, b, rest)` with `Cond = Le(a, b)` over atoms; `seq`/`block` write a list of statements. The meaning and the run take the arm the test picks, then the rest. `check_body` answers the final places with the residuals (`Option<Next>`), so an arm's places can be joined: `join` needs the arms to bind as many words and views (an arm's words are the join's values, a phi's), and its live views are `meet(a, b)`: a view live on both arms in one mode stays, its region `a.coarsen(b)` (itself where the arms agree, else the union `Both(a, b)`). An arm's residuals are `Under(test, arm, owed)` (`under`), which holds where `test(ws) = arm → owed`. A region is now `Whole | Win(lo, n) | Both(a, b)`, licensed piece by piece (`Region::license_win`), and its meaning is pointwise: `Region::hits(r, ws, p)` and `Region::Clear(a, b, r, ws)`: no position covered by both. Coarsening a disagreement to the whole object was tried first and refused writes apart from both arms' windows (the program `coarse` writes at 2 beside views at 0 or 1); the union is exact, the design's "a join is the union of the place sets", and its proof is simpler (`ViewOk::coarsened` is one line).

  Proved: `check_body_sound(k, inr, ops): BodyOk(k, ops)`, by the body's shape: `end_ok`, `do_ok` (a statement then the rest), `if_ok` (unpacks the verdict by `Next::then_some`, `if_head`, `check_join_sound`; splits on the test; `if_taken` runs whichever arm was taken through its own induction hypothesis, weakens the invariant to the join's places by `Sim::weaken`, then runs the rest). `BodyOk` quantifies over any final words the body's meaning reaches (a `Prefix`), so an arm's residuals are read in the function's final words, where the arm's words are the taken arm's. `Sim::weaken` from `Joins(c, c2)` (same counts; each live view of `c2` is `Covers`-ed by one of `c`: same name and mode, a coarser region): `weaken_view`, `weaken_lent`, `weaken_excl`. `meet_covers` gives both arms' covers. `Owed::all_under` reads an arm's residuals under the test, `Cond::test_stable` reads the test in the final words.

  Programs: `branch` (`let t = &x[0..k]; let a = if k <= j { x[j] := 5; t[0] } else { dead(t); x[0] }; x[0] := 9; a`): `branch_checked` (one residual, `Under(Le(k, j), True, Spans(0, k, j, 1))`), `branch_owed` (one `omega` from the test), `branch_sound`, both arms run and meant at base 1 (`branch_runs_first/second`, `branch_means_first/second`). `coarse` (views opened on different windows in the arms, live after the join with the union region; a write at 2 beside them is accepted, decided at literals): `coarse_checked` (nothing owed), `coarse_sound`, `coarse_runs_first/second`. Controls: `after_join_refused`/`after_join_control` (t read after the join, where the second arm ended it: refused; the runs differ, 9 against 5); `unguarded_checked`/`unguarded_fails`/`unguarded_control` (the same write without the branch: its residual fails at `k = 1, j = 0`, the runs differ, 5 against 3); `swapped_checked`/`swapped_fails`/`swapped_control` (the write in the other arm owes the residual under the test failing, where it fails; 5 against 3); `coarse_held_refused`/`coarse_held_control` (a write into either arm's window while the joined view lives: refused, and where the second arm is taken the runs differ, 7 against 6); `uneven_refused` (arms binding different word counts do not join).

  Refuting conditions for this item. *Does a join need more than the meet and a coarsened region?* No. The proof needs no per-arm bookkeeping that survives the join and no flag: the arm taken has the invariant at its own places by the induction, and the meet's places are a weakening of either arm's. One requirement the design did not state: the arms bind as many words and views as each other, so the numbering after the join is static (a phi's values); a language with scoped arm locals would number the join's values instead. *Can a residual under a branch be closed data with the condition as hypothesis?* Yes: `Under(test, arm, owed)`, a constructor of the residual, holds as `test(ws) = arm → owed`, read in the final words since the test's atoms are bound before it (`Cond::test_stable`); `branch_owed` discharges it with one `omega` from the test. Cost: `if_ok` 235k kernel steps, the join's lemmas each under 15k; the module elaborates in about 20 s fresh.

- 2026-11-25: Item 5, stored references and the erased owner: built and proved, within one restructured checker. `Mode` gains `Lends(n)`: the parameter is `n` write references stored in a collection, into an erased owner. In the meaning such a function takes the owner's value in and out with the slots of its references (`World.mean` takes the lent `List<Slot>`; `Sem::start` makes its first state, the references' values being the owner's windows at their slots); in the run it is given the references (`World.run` takes `List<Ref>`) and no owner reference (`Mode::owner` is `Ref(0, 0, 0)` for it). It starts with its references live (`lent_views`), cannot use its owner (`Set`, `Get`, `View`, `CallView` need `Mode::owns`) and answers a word (`check_fn`). A caller hands it live write views with `CallAll(g, ts, args, z)` (`check_all`: the callee's `elems` is `ts.len()`, every `t` lent, none twice (`all_lent`), the caller writes); the call consumes them (`kill_all`) and the owner comes back (`Sem::returned`).

  `FnSafe` quantifies over the lent slots with `Lendable(mode, r, lent)` (as many as the mode says, narrowed from `r`, pairwise apart) and is stated at `r`, the owner's place, which the run is not given; `Safe` gains `kept_out`: a lending function changed nothing outside the lent references' spans. Inside a lending function the invariant gains `Sim.kept` (no view opened beyond the lent ones, and nothing outside them changed), kept by `backed_kept` and vacuous for owner statements, which a lending function cannot reach. Proved: `start_sim` (the lent references are the first live write views, `start_view`, `start_lent`, `lent_views_mem`, `ref_at_map`/`list_at_map`/`word_map`), `Sim::all_core` with `all_lendable` (the collection's exclusivity from the caller's `Sim.excl` and `all_lent_distinct`), `all_refs` (the run's references are the meaning's slots narrowed, `Lent::renarrowed`, `narrow_cut`), `all_keeps` (every view not in the collection is kept by the callee's frame), `all_kept_frame` (a lending caller's own frame), `step_all`; `Sim::ends` by the owner case (`Ret::word_view` for a lending function's word answer); `check_sound` over any lent slots; `check_owned`/`owned_checks` (a function that holds its object, stated at its first state with nothing lent, as before); `fn_safe_answers`/`Posted` over lent slots.

  Programs: `fill2` (`Lends(2)`: writes through both references and answers what it reads) and `pair` (`let t = &x[0..1]; let a = &mut x[k..k+2]; let b = &mut x[j..j+2]; let z = fill2([a, b], 7); let y = x[j]; t[0]`, stating `1 <= k`, `k + 2 <= j`): `fill2_checked` (owes nothing), `pair_checked` (the loans apart from `t` and each other, the callee's precondition), `pair_owed`, `pair_sound`/`fill2_sound` (every depth), `pair_runs`/`pair_means`/`pair_words` (base 1; 7 written through both in place), `fill2_runs` (the callee's run given `Ref(0, 0, 0)` for its owner and two references) and `fill2_means` (its meaning: the owner in and out, eager write-back at each slot). Controls: `twice_refused`/`twice_control` (one view lent twice: in the run both writes land in one place, in the meaning the second write-back puts back a stale copy, 1 against 6), `reuse_refused`/`reuse_control` (a consumed view read after the call: 7 against 6), `peek_owner_refused`, `view_owner_refused`.

  Refuting conditions for this item. *Can the frame be stated without naming every object reachable?* Yes: `kept_out` quantifies over the lent slots, outside whose spans nothing changed; it names one place besides them, the owner's reference, once per owner (per region parameter, §15.8), not per object reachable. *Does the erased owner make a caller's proof depend on a callee's body?* No: `pair_sound` cites `fill2`'s `FnSafe` only, applied at the caller's own reference, which stands for the owner. What the promise needed beyond place states: that reference, quantified in `FnSafe` and absent from the run (a ghost name for the erased owner's place, which is the meaning's erased slot seen from the run side); no separation algebra and no ghost state in the invariant, whose new clause `kept` follows from a lending function having no owner to touch. Untested, and where it would next bite: a collection held as a value in data across statements rather than formed at the call (here the stored references are the call's argument), references into several owners (several region parameters), and places with steps (this checker is one list per object; the generalisation to `steps.hthr` is untested).

  The verdict's shape (refuting condition: linear once there are several objects, loans and joins): measured per `docs/proof-patterns.md` §7, one cache warmed on the library prefix and a new declaration per size, steps from `--timings`, on generated programs of 2 to 64 units of ten statements (a loan written through and read beside a long-lived view, an owner read beside it, its death, then a branch whose arms open views on different windows, live after the join as a union, then a write beside it): `check_fn(…).is_some()` costs 7.1k, 14.0k, 27.8k, 55.6k, 112.1k, 228.0k steps (literal windows) and 6.5k to 211.4k (open windows owing two residuals a unit); the full verdict `check_fn(…) = Some(rs)` with the residual list spelled out costs 9.2k, 18.0k, 35.7k, 71.2k, 143.1k, 290.0k. Each doubling is 1.96 to 2.03 times the last: linear. Several objects per function were not built (one object per function throughout), so the holder table as a map stays untested.

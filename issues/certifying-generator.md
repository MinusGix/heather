The `runtime_func`-style generator: intensionally analyze boxed function code
and emit a `Compile` instance *plus its equiv proof*. Because each output
carries its own certificate (checked by the kernel like any proof), the
generator itself needs no verification — it can be heuristic, incomplete, or
user-written, affecting only *which* functions compile, never soundness.
Protect this property as the design evolves.

Surface form TBD: possibly not a named wrapper but a macro over
`eval(generate(box f))`.

## Current state (rewritten each round; the log below is archive)

As of 2026-08-14: the fragment covers first-order structural recursion with
parameters in all three tiers — Nat, payload-free tier-0 enumerations
(matched via a root `Term::Case`, passable to callees), and ONE
unparameterized tier-1 inductive recursed over structurally — results Nat or
tier-0 enumerations, cross-function calls composing throughout (Prog =
topo-ordered callee closure; callee invariants re-derived per program until
[[prog-extension-lemma]]). Machinery split: crates/elab/src/certgen.rs is the
rim (fragment check, marker passes); the frozen in-language walker lives in
lib/certgen_code.hthr, the certificate expression in lib/certgen_cert.hthr,
the once-proved existential kit in lib/ir_v1.hthr. Design docs:
certifying-generator-design.md (v1/v2 core), certgen-non-nat-embeddings-design.md,
certgen-tier1-source-types-design.md, certgen-tier0-params-design.md,
certgen-cert-expression-design.md (§8.1: what may touch CertOut). Remaining
of doc §8 item 2: parameterized instantiations (with [[datarepr-separation]]);
then loopification and [[prog-extension-lemma]]. Costs and rails live on
[[certgen-harness-cost]].

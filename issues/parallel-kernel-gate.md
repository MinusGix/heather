Check independent declarations' proofs on a pool of kernel workers while the elaborator continues serially: a deferred kernel gate behind the existing `KernelGate` seam, over `Arc` kernel terms.

## Why

The full lane's tail is five native certificate targets of one shape: thousands of small, successful, evaluator-bound theorems in a wide, shallow dependency graph ([[function-ir-x86-proof-scaling]] 2026-09-11: 3 474 items, 86 s kernel of 128 s, no failures). The kernel cannot check two of them at once because every term child is an `Rc`. Proof count only grows from here — no theorems about real programs are being checked yet.

The Arc-tax control ([[kernel-arena-terms-frozen-prefix]], 2026-09-11) says the serial cost of `Arc` is ~2% at module scale (1.04x bench median; 1.2–1.28x only on the refcount-dense nat micro-steps), so `Arc` plus a worker pool is affordable now; the arena representation remains the allocation project and is not what parallelism waits on.

## Design points (settled)

- **Deferred gate.** For each declaration: the statement's type is checked synchronously (dependents need it), the binding is committed to Ψ, and the proof/body check is queued with the Ψ prefix it must be checked against (Ψ is persistent — sealed chunks plus tail — so the snapshot is O(1)). The module joins all outstanding checks before it is accepted, published to any cache/image, or emitted (`build-x86` writes nothing before the join). Any failure fails the module, reported deterministically in declaration order.
- **`Arc` by alias** (`use std::sync::Arc as Rc` workspace-wide, as measured); a proper rename is a mechanical follow-up. Per-worker checker state (`Tc`, its `RefCell` memos, the value arena, `BodyCache`) — nothing shared but the frozen prefix.
- **Borrow the prefix, clone only what you build**: workers hold references into the shared prefix where the evaluator allows it; every avoided clone is both serial tax and contention removed. Audit the nat step paths' clone/drop pairs as part of this.
- **Worker count** from `--kernel-workers N` / `HEATHER_KERNEL_WORKERS`, default 1 = today's serial behaviour and error timing, so the test suite and its 4 GiB per-process rail are unchanged until the default moves.
- **Attribution survives.** The stats registry is thread-local; each worker's timers and counters are folded back into the declaration's row at join time, so `--timings` still reads kernel_gate per item.

## Measurement (the datum this round exists to produce)

`reused_callee` `build-x86`, release, warm image cache, same furnace instance, workers = 1, 2, 4, 8: wall, summed kernel_gate, peak RSS. Linear to 8 means contention is a non-issue; flat past 2 means the frozen-prefix borrow discipline or [[kernel-arena-terms-frozen-prefix]] comes first. Plus `scripts/bench --check` against a same-box Rc baseline to confirm the serial tax stayed where the control put it.

## What it assumes from elsewhere

- **[[parallel-checking-and-caching]]** owns cross-process parallelism and the shared telescope. Assumed here: only that in-process kernel parallelism is a component it can build on, not a replacement.
- **[[kernel-arena-terms-frozen-prefix]]** owns the representation question. Assumed here: the Arc-tax number, and that its scaling curve is an input to that decision.
- **[[perf-instrumentation-consolidation]]** owns the timers; the elaborator's serial 32 s is the wall right after this lands and needs its `other` bucket named.

The curve flattens against Amdahl's other half instead: the item rows say elaborator-side work is 122.4 - 89.4 = 33 s of the certificate, and the wall at W>=4 is that plus the serially-checked library modules. W=2 already exceeds the naive Amdahl prediction because the deferral *pipelines* — the elaborator keeps elaborating while workers check — so the model is max(serial elaborator, kernel/N), not serial + kernel/N. The next lever on this workload is naming and shrinking [[perf-instrumentation-consolidation]]'s 'other' bucket, or [[parallel-checking-and-caching]]'s cross-process split; it is not more kernel workers. RSS grows roughly with width (one value arena per worker in flight) — worth a rail if the default ever moves off 1.

**What landed.** `use std::sync::Arc as Rc` in 117 workspace files (a rename to `Arc` is a mechanical follow-up). `crates/elab/src/pool.rs`: owned `Deferred` items over an O(1) `Arc<GlobalCtx>` prefix snapshot, `std::thread` + one Mutex/Condvar (elab gains no dependency), outcomes sorted by submission index, worker panics caught. `--kernel-workers N` on check/build-x86/compile-x86 plus `HEATHER_KERNEL_WORKERS`; **default 1 spawns no thread and runs the gate inline**, so the suite and its rails are untouched. Deferred at the two Psi sites (`elab_decl_inner`, `push_gen_def`); `quote.rs`'s `meta fn` stays synchronous on purpose, because its body is *executed* by the interpreter later in the same module. `join_kernel_gate` at the end of both module paths, so the semantic image, the declaration cache, `heather check`'s verdict and every `write_new` are behind it by construction. Attribution folds back: the worker returns its ns and its `kstats` delta, the join merges them into the joining thread's counters (for still-open module/run scopes) and patches the already-closed item row, so `--timings` keeps one `kernel_gate_ns` per declaration. Kernel diff is two inert functions (`Snapshot::plus`, `merge`) and one DESIGN.md paragraph; no new judgement.

**Soundness note worth keeping:** the serial gate never pushes a failed declaration to Psi, the deferred gate does. So a declaration after a failure may have been checked against an unverified body, and `accepted` is replayed only for the prefix *before* the first failure — a failing module records fewer cache entries under W>1 than under W=1, deliberately. Fuel is what bounds what an unchecked body can do to the rest of the module, and a `theorem` (the whole certificate workload) is pushed opaque, so dependents never see one.

**Deliberately not done.** (1) The clone/drop audit found exactly one pair and it is structural: `subst.rs`'s `sub_ty`/`sub_tm` build every unchanged node and drop it, which is precisely where the 1.2x lands. Removing it is a rewrite of every arm of the map traversal in the trusted base and wants its own round with these four families as the acceptance number — filed as [[subst-rebuild-then-discard]]. (2) `--cache` with W>1 costs one full Merkle-prefix rehash per module, because the first replayed verdict arrives with a Psi shorter than the prefix the intervening `admits` grew and `Inner::sync` answers a shrinking Psi by clearing. Correct, measurable, and no path runs that combination today; the proper fix is a third seam method that computes an item's identity at submission and commits the verdict at the join. (3) A deferred failure loses `kernel_error`'s notes (refused_decide, pending mismatch/refl), because that state has moved on by join time; the error, item and span are exact.

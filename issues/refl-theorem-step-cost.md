Datum, 2026-09-16 (release + value-metrics, `--kernel-workers 1`, tree a6ba37a), `docs/showcase/calc_parser.hthr`: the fourteen closed refl theorems — `parentheses` 1 278 ms at 1 558 queries / 8 777 steps, `executed_parentheses` 1 095 ms at 1 669 / 8 948, `nested_parentheses` 1 042 ms at 1 195 / 7 012, `wrong_close` 1 030 ms at 878 / 3 467, `missing_close` 1 014 ms at 746 / 2 791, `precedence`/`executed`/`evaluated`/`product_before_sum`/`doubled_operator`/`missing_rhs`/`missing_product_rhs` 550–600 ms each at ~700–1 400 queries and 2 500–6 000 steps — together ~12 s of the showcase's 64.5 s serial total, almost all of it kernel gate, at 0.1–0.7 ms per step and ~0.8 ms per conversion query. Elsewhere in the same run a step is ~3 µs and a query ~2 µs. The steps and queries are few; the seconds are in what each step touches: a closed run of the certified parser over five to seven tokens, through `Certified`/`rebase`/`le_trans` values that carry their proofs, on a small-step rewriter that copies branch bundles per β ([[whnf-sharing-term-growth]]'s mechanism, closed for the exponential axis, not for this constant). Unfueled costs — forcing, weakening, instantiation — are where a fuel pin cannot see. Not on the eight-worker critical path (each item is ~1 s), so second behind [[quoted-component-traversal-remainder]]. Attribute one item (`parentheses`) by profiling the kernel's time per rule, not by counters; the term-level/type-level asymmetry of [[type-level-reduction-over-computed-operands]] may be the same family. Related: [[parser-certified-composition-cost]], [[whnf-sharing-term-growth]].

## Log

- 2026-09-18: Attributed (2026-09-18, desktop, release, width one, through `heather check --cache --only`; tree c329f1c plus three inert kernel counters landed with this entry: `shift_global_nodes`, `delta_body_rescopes`, `global_ref_rescopes`, read as `rescope`/`unfolds`/`refs` by `scripts/timings`). The seconds are **global rescoping**: `Defs::body` rescopes a definition's body with `shift_global(v + 1)` into the ambient Ψ, memoized in a `BodyCache` that is created per `typing::check_term` — so every gate call re-copies every definition it unfolds, and a refl theorem over the certified parser unfolds the parser. `parentheses`: 985 ms gate, 8,869 steps, 116 body rescopes, **6,498,759 nodes walked by `shift_global`**; a scratch split of the counter by site put 6,524,542 of the run's nodes under `Defs::body` and the `u^δ`/`U^δ` rules' per-occurrence context/type rescoping at 239 k for the whole run — the bodies are the cost, the references are not. The floor is the tell: `empty_input` (`parse([])`, 932 steps, 10 misses) is 357 ms gate at 2,829,198 nodes / 81 rescopes, i.e. ~350 ms per theorem before the input has any length, and `single_number`/`missing_rhs`/`extra_close` sit on the same floor (2.9–3.0 M nodes, 316–330 ms). `perf` self-time agrees: the item's marginal profile over the `empty_input` control is `map_term/map_type::<ShiftGlobal>` plus `Arc<Term>`/`Arc<Type>`/`Level` drop glue and malloc, ~80 % of the delta (DWARF unwinding gave no user frames on this box; the counters are the attribution). Whole root module of `docs/showcase/calc_parser.hthr`: 105.4 M nodes rescoped over 5,067 body rescopes, 29 items over 500 k nodes summing to 100.7 M nodes and 16.8 s of the module's 18.5 s gate — at the measured ~150 ns per node, rescoping is most of the root module's kernel time, roughly a third of the file's cold check and a larger pot than `complete_post`'s. `Grammar` (3.3 M) and the `*_body` items are the same family. A cross-item cache does not help: the shift amount `v + 1` differs for the same binding in every later Ψ. The fix candidate is to stop shifting: evaluate an unshifted body in the value machine under a global-index offset carried by the syntactic closure (`TmClo::Syn` gains a `gshift`, applied when a `GlobalTm`/`CtxBase::Var`/`SubstTail` in the body becomes a value or a lookup — `ShiftGlobal` done lazily, at zero copies), with `CloId` including the offset; the rewriter path (`reduce.rs:391`, typing's cold whnf) keeps the eager shift. Its adequacy is one equation, `eval(shift_global(k, t), ρ) = eval(t, ρ) at offset k`. `scripts/perf report` now prints gate µs per step and the rescope column per item and a per-step outlier section, so this family is visible in a table sorted by total.
- 2026-09-18: Fixed, by not shifting: the value machine evaluates a definition's body **as stored**, under a global-index offset carried by the closure's environment (`docs/kernel/lazy-global-offset-design.md`; `Env` gains `gshift`, `Defs::body_unshifted` beside `Defs::body`, and the offset is spent eagerly only where syntax leaves the value path — a box's payload, a `ctx`, an annotation, a recursor table — and above a global binder, which keeps every pending offset at cutoff 0 and keeps `letbox`'s β substituting ambient code into an ambient body). Measured on desktop, release, width one, tree 65ce77d plus this change; the "before" column is the same tree with only the kernel diff stashed, re-measured today.

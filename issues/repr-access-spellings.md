Spun off [[datarepr-surface-ergonomics]] item 5, user-confirmed wanted
(2026-08-15). Hand-written certificates today must spell minted names
(`Repr_ListTok::…`, `Impl_ListTok_length::…`, `ListTok_spec_rec`) and
there are TWO spellings for the same access
(`ListTok().mk_Cons(t)` vs `Repr_ListTok::mk_Cons()`), the split forced
by [[theorem-field-projection-oom]] and
[[receiver-method-shadows-record-field]]. The legitimate access points —
the ones user code is *supposed* to reach, as opposed to the internals
[[unnameable-generated-names]] will mark — deserve one designed spelling
(`ListTok::fold`, `ListTok::mk_Cons`, …-shaped), with the workaround
split dissolved rather than papered over: fixing the two underlying
defects is likely the first half of this issue.

## Log

- 2026-08-15: The obligation-records design (docs/obligation-records-design.md §3) hands this issue the REFERENCE spelling deliberately, and hands it a shape to extend. Probed lexer/parser facts it should build on: 'A::b' is a SINGLE lexer token with exactly one join (lexer.rs:130-137), so no three-segment '::' path exists to be spelled; '::' never follows an application (every 'Impl(f, Rp)::refines'-style candidate is a parse error today); '@' is claimed as a PREFIX (fully-explicit call, parser.rs:2492); '.'-chains ('Impl(add, BinNat).refines', 'BinNat.impl(add).refines') parse today and reach name resolution. The design takes '<owner>.<slot>' for the proof-declaration head ONLY, as a KEY resolved in the slot table rather than as an expression — precisely because a dot on an assembled repr/impl value is theorem-field-projection-oom. Consequence for this issue: a dot-shaped REFERENCE form is blocked on fixing that defect first, and until then hand-written proofs keep spelling the minted namespace paths (Impl_Rp_f::refines(), Repr_N::abs()).
- 2026-08-15: Shape handed over (2026-08-15) by the obligation-records round: an obligation's printed path is '<owner>::<obligation>' — 'Impl(add, BinNat)::refines', 'BinC::Succ_inv' — chosen on semantic grounds (an obligation is a member of its owner's namespace and '::' is the member operator), ratified by user verdict with the standing instruction that a lexer artifact is a cost to pay and not a vote to count. In v1 it is PRINT-ONLY: it appears in '?' messages, failure diagnostics and 'heather obligations', and nothing parses it, because under inline-first nothing references an obligation from outside the declaration that owes it. So this issue inherits '<owner>::<obligation>' as the shape to extend for REFERENCE position, and two notes with it: the grammar cost is real and unpaid (A::b is one lexer token with one join, and '::' never follows an application, so an applied-owner path needs a new production that modules will force anyway), and the '::' form is the one that does NOT inherit theorem-field-projection-oom, because '.' means value projection and that is the operation that aborts. Citing a certificate inside another proof still spells the minted 'Impl_BinNat_add::refines()'.
- 2026-08-15: UNBLOCKED (2026-08-15): [[theorem-field-projection-oom]] is fixed and closed — projecting a theorem-valued field off an assembled record value now checks (named projections, gendefs.rs), so the dot-shaped REFERENCE form this issue was told to design assuming the fix is free to proceed. Two facts carry over: '.' now genuinely means value projection at law fields (linear, not exponential), and the declaration-time cost of the device is tracked at [[record-projection-defs-declaration-cost]].
- 2026-08-16: DESIGNED AND LANDED (2026-08-16): docs/repr-access-spellings-design.md, plus the parser/resolution/tooling changes that make it real. The rule: every access point of a repr or an impl is reached as <owner>::<member> where the owner is the name the AUTHOR wrote — BinNat::abs, BinNat::fold_law, BinNat::spec_rec, Impl(add, BinNat)::refines — and the elaborator's minted names (Repr_N::…, N_spec_rec, Impl_R_f::…) are not spellable in user source at all.

The first half of the issue's own guess was right but cheaper than expected: the two defects that forced the two-spelling split are both spent. theorem-field-projection-oom is fixed; receiver-method-shadows-record-field was RE-PROBED and does not reproduce at any repr access shape (resolve_dot takes the record-field route before the method desugaring the builtins sit behind, and a repr value's type always infers) — its narrowed residual (a receiver whose type cannot be inferred) is logged on its own issue and is not on this path. So the split was two workarounds, one already evaporated, and nothing landed here is bent around either.

Key decisions and their reasons. (a) The designed name is NOT the declared name: N::abs is a resolution ALIAS onto the declaration Repr_N::abs, because the artifacts are emitted as surface text (so declaring under N::… changes emission bytes, which idiomatic-spelling-pass owns), because N names a value and a member's qualifier must name a type, and because keeping the two distinct is exactly what unnameable-generated-names needs. (b) One spelling means the other refuses: a minted name in user source is an error naming the designed form, and generated source is exempt by MODE (Elaborator::generated_mode, and the new public elab_generated_source that the perturbed-emission mutation controls now use — without it those controls would have started passing on the refusal of a name rather than on the mutation, which is the one failure a control cannot tolerate). (c) '.' stays ordinary record projection, definitionally equal and not canonical (a generator consumes laws before the value they are fields of exists; projection at a law field rests on the named-projection device whose declaration cost is record-projection-defs-declaration-cost; eta at a neutral receiver at that size is still an OutOfFuel); its one designed job is the carrier, N().R, which has no namespace member because the emission spells the carrier's own type name. (d) The grammar cost is paid deliberately: one postfix production ('postfix :: ident') for the APPLIED owner — the standalone ColonColon token existed only inside 'import m::{…}', so every expression followed by '::' was a parse error before — and it builds ExprKind::Var of the path as PRINTED (the owner rendered structurally), not a new ExprKind, so the referenceable string and the string the tooling prints are the same string by construction and no ~25-variant AST walk changed. v1 is one applied owner; modules will force the general multi-segment lifting and this arm is where it goes.

FINDING that moved the design mid-round: the four via-abs artifacts (N_emb, N_emb_inv, N_emb_abs, N_fold_via_abs) were drafted as INTERNALS with no spelling, on the line 'an artifact whose existence depends on how a clause was filled is an internal'. The defaults round's own test — that the embedding is a real computing function — is a standing customer that refuted it, so they are designed members (N::emb, …) and CONDITIONAL: they exist only where fold defaulted, and where it did not, 'N::emb' is 'BinNat has no member emb' with the member list printed. The internals category kept only what is a step in HOW a clause was proved (Impl_R_f::via_derived_obligation) and the assembled Impl value (reached through the registry, never by name). Sharper line: a route's intermediate is an internal; a declaration's artifact is not.

FINDING that the design had to absorb: 'heather obligations' printed STATEMENTS full of minted names, and a statement is precisely what an author copies to write the proof — so under the new rule it was printing something unwritable. Statements are now de-mangled at the DISPLAY boundary (the listing and the '?' reporting hole) while the stored strings, which are the types the generated declarations are checked against, are untouched. A test takes a statement out of the listing programmatically and uses it verbatim as a theorem's type.

Implementation: crates/elab/src/access.rs (new — alias/refusal/display table, registration from elab_datarepr and elab_impl), key_of's alias fallback and a new NameRes::Restricted carried into miss_msg, generated_mode + elab_generated_source, one postfix arm in the parser. Emission bytes unchanged — verified by the emission-text assertions, which still spell the minted names because they are assertions about generated source. Migrated to the designed spelling: the reprgen hand-runs, the datarepr acceptance tests, obligation_records, record_projection_size and the CLI listing fixture's assertion.

Tests: crates/elab/tests/repr_access.rs, 17, over the docs/testing-generated-terms.md axes (literal AND neutral carrier values, the open element type Tok, checking positions throughout) with eight negative controls — each minted family refuses and names its designed form, an unknown member prints the member list, an access path with no impl behind it names the missing declaration, a bad owner is a parse error, the generated-mode exemption does not leak past the emission, and the alias does not shadow a real type's member.

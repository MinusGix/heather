title: Give the loop generator stores, for stateful loops that emit bytes

Certified loops execute through `ExecuteAccess`, whose `AccessCode` has no
store, and `LoopHead` keeps memory unchanged across an iteration. A program's
stores exist only as single `StoreStep`s in library process proofs.
[[native-tr]] keeps its map loop out of the generator for that reason: it
has no state, so a library loop around a generated byte map suffices.

A loop whose step keeps state and emits zero or more bytes needs the
generator itself to store: an output cursor apart from the input cursor, a
store in `AccessCode`, a loop invariant over the memory written so far, and
output pieces in the typed publication. `tr -d` (the output is shorter) and
`tr -s` (state across bytes and chunks) are the first customers, and many
filters have the same shape (`cat -s`, `dos2unix`).

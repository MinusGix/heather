Probed 2026-08-07: `fn f(g: (x: Nat, y: Nat) -> Nat)` fails to parse at the comma — a surface function TYPE takes exactly one binder per arrow, so class fields and higher-order parameters write `(x: A) -> (y: A) -> (z: A) -> …` (see lib/std/algebra.hthr's law fields). Application is already fine: `op(op(x, y), z)` and `le(x, x)` both check against curried types.

Two additions, one decision:

1. **`(x: A, y: B) -> C`** — comma-separated binders in one arrow group, desugaring to the curried Π chain. Pure parser sugar; later binders' types may mention earlier ones (it is a telescope).
2. **Shared annotation** for same-typed runs. Candidates: Lean's juxtaposition `(x y z: A)` — works only because parameter modifiers (`self`) are keywords, so it is fragile against new modifiers and reads as application in other positions; or the comma form `(x, y, z: A)` — names separated by commas, one trailing annotation, consistent with the language being comma-separated everywhere else and unambiguous against modifiers (a modifier still prefixes a single name: `(self x: A, y: A)`). Leaning comma form (user + assistant agreement 2026-08-07); the same sugar should apply in fn/theorem parameter lists, not only in types.

Cleanup rider when this lands: normalize algebra.hthr's law spellings (also switch the one curried `le(x)(x)` to `le(x, x)` now — supported today).

## Log

- 2026-08-09: Landed, as parser sugar only. `(x: A, y: B) -> C`, the shared-annotation run `(x, y, z: A) -> C`, and every mix (`(x, y: A, z: B) -> C`) parse and are **curried in the parser** (`curry()` in crates/syntax/src/parser.rs), so the AST is byte-identical to the hand-written chain and no elaborator, printer, kernel or test downstream learns a second representation. It is a telescope for free: the domains are parsed left to right and folded at the end, so `(A: Type<0>, x: A) -> A` needs no rule of its own. The same run works in fn/theorem parameter lists (`fn add(a, b: Nat)`) and in implicit groups (`{A, B: Type<0>} -> …`, `{a, b: Nat}` as parameters) — the brace form was free once the paren one existed and is included rather than left as a wart.
- 2026-08-09 (decisions): (1) The COMMA form, as decided 2026-08-07, and the modifier case is now the *test* that says why: `fn r(self x: Nat, y: Nat)` is two parameters, and `self x, y: A` is REFUSED by name ("`self` marks a single parameter") rather than guessed at — the refusal is what juxtaposition could not have stated. (2) Grammar disambiguation: the three-token `( Ident :` lookahead grows one arm, `( Ident ,`, decided by a scan (`group_binds()`) for a `:` at the group's own paren depth (record-literal and bracket interiors skipped) OR a `->` straight after the group. Both discriminators are already outside the expression grammar, so this is additive and needs no backtracking; `(a, b)` with neither is untouched, and expression parsing does not move. (3) The `->` disjunct exists purely for the diagnostic: `(x, y) -> C` reaches the binder-list parser and is told "this binder group has no type: write `(x, y: A) -> B`", instead of failing at the comma with `expected )`. (4) A run shares one annotation by cloning the domain, so `(x, y: A)` and `(x: A, y: A)` are the same nodes.

# Issues

Repo-local issue tracker: one markdown file per issue, frontmatter for metadata,
`INDEX.md` generated by `scripts/issue`. Optimized for grep/Read access (Claude)
and CLI browsing (human).

## File convention

Filename: `<slug>.md` (kebab-case, stable — it's the link target).

```markdown
---
title: Short imperative title
status: open          # open | blocked | closed
thread: T1            # optional; work thread (see THREADS section below if/when we add one)
labels: [kernel, ir]  # optional
blocked-by: [other-slug]  # optional; slugs of blocking issues
code: crates/kernel/src/term.rs:120 @ 980b47e  # optional; path:line @ commit
created: 2026-07-22
updated: 2026-07-22
---

Body: problem statement, then iterative notes appended under `## Log` with dates.
Link related issues as [[other-slug]].
```

- Code references are `path:line @ shorthash` — resolve with `git show <hash>:<path>`.
- History of an issue: `git log --follow issues/<slug>.md`.
- Closing keeps the file (set `status: closed`); it stays greppable.

## CLI

```
scripts/issue list [--status S] [--thread T] [--label L]   # table of issues
scripts/issue show <slug>                                  # print one issue
scripts/issue new <slug> --title "..." [--thread T] [--labels a,b]
scripts/issue close <slug> / reopen <slug>
scripts/issue log <slug> "note"                            # dated entry under ## Log
scripts/issue threads                                      # per-thread status counts
scripts/issue check                                        # lint links/blocked-by/index
scripts/issue index                                        # regenerate INDEX.md
```

Mutating commands (`new`, `close`, `reopen`) update `updated:` and regenerate
`INDEX.md` automatically.

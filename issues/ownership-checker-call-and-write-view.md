The second experiment of `docs/language/ownership-design.md` §15.6: one call with a `&mut` window and a returned view, over [[ownership-checker-spike]]'s module (`lib/lang/ownership/place_check.hthr`). Library only.

## Scope

- **Write views**: `let w = &mut x[lo..lo+n]`, writes through `w`, and the place's `out(viewer)` state; eager write-back (§15.2) in the meaning, so `eval1` updates the place after each statement that may change `w`.
- **Deaths**: a binding that dies at a site, from the annotation (§15.3), restoring `whole` or removing a viewer.
- **One call**: a callee's signature as data (modes, the region of its result, whether the result is fresh or one of its parameters), checked at the call; the callee's own `check_sound` as what the caller cites.
- **A returned view**: the call returns a read view of its `&mut` argument's window, frozen in the caller after the loan ends.

## What the first experiment says will change

From the spike's log (2026-11-25): the place state stays per object, but an object's state becomes per span (whole, frozen windows, out windows) instead of one holder and a table of read views; `Residual` becomes a sum (apart, and below its length for a write through a window); the meaning's object environment must allow write-back to a name (the spike's is append-only); and `Inv.held` weakens to "the buffer holds the holder's value outside its out windows, and each out window holds its viewer's value", which is where "a usable place reads its value" is first tested against a loan. The step lemmas for get, read, view and clone carry over unchanged; the set step's frame becomes `PathIn::agree_apart` over a window path instead of an element.

## Done when

The fragment with those four additions has `check_sound`, with one accepted program per addition and a `¬` control for each refusal, and the log answers whether the place-state invariant still suffices.

## Log

- 2026-11-25: Built and proved. `lib/lang/ownership/call_check.hthr` holds the fragment, its meaning and run over a world of callees, `check_fn`, `check_sound` and `prog_sound`; `lib/_tests/lang/ownership/call_check_tests.hthr` holds the three programs, their controls, and probes of the run's rebasing. The first experiment's module is untouched and its programs still pass.

  **The fragment.** A function (`Func`) takes one list parameter, to read or to write (`Mode`), and words, and answers a word or a read view of its parameter (`Ret`). Statements: `Set`, `Get`, `View`, `Read` as before; `Die(t)`, the death annotation (no code); `CallMut(g, x, lo, n, args, y, z)`, `let (w2, z) = g(&mut x[lo..lo+n], args); let y = x.put_window(lo, w2)`; `CallView(g, x, args, t)`, `let t = g(&x, args)`. `mean_fn` is the meaning, with window, call and `put_window` in the meaning of `CallMut` (§15.2's eager write-back). `run_fn` runs on a reference `Ref(b, base, len)` into a file of buffers, with no copy: a lent window is the reference narrowed (`narrow`), and a returned view is two words relative to the reference, which the caller rebases (`Exec::viewed`: `Ref(r.b, r.base + o.lo, o.n)`). Both are stated over a `World`, the meanings and runs of the callees as functions, so a body's meaning and run never see a callee's body. `world(fns, d)` is a program's world at depth `d` of calls.

  **Proved.**
  - `FnSafe(sig, pre, mean, run)`: for every file, reference in bounds (`InRef`) and words of the signature's count meeting `pre`, a `Safe`: the run answers the meaning's word (`answer`); the window holds the meaning's value and nothing outside it changed (`on: OnRef`, pointwise: `holds`, `out`, `other`, and the lengths); a read parameter's value is what went in (`keeps`); the view answered lies inside the reference (`view_in`) and reads the meaning's view value (`view_reads`).
  - `check_sound(sigs, pres, f, rs, ok: check_fn(sigs, f) = Some(rs), pre, w, discharge, callees: (g) → calls(f.body, g) = True → FnSafe(sig_at(sigs, g), pres(g), w.mean(g), w.run(g))): FnSafe(f.sig(), pre, mean_fn(w, f), run_fn(w, f))`, in any world. Stages: `step_set`, `step_get`, `step_view`, `step_read`, `step_die`, `step_mut`, `step_view_call` (dispatched by `Stmt::step`), the cores `Sim::stored`, `Sim::lent`, `Sim::viewed`, `Sim::said`, the end `Sim::ends`, and `check_body_sound`. The write-back is its own lemma over bare data, `written_back` (with `written_at`, `put_cut_in`, `put_cut_out`, `put_cut_length`).
  - `prog_sound(fns, pres, ok: ProgOk(fns, pres), d): (g) → FnSafe(sig_at(sigs_of(fns), g), pres(g), world(fns, d).mean(g), world(fns, d).run(g))`: every function of a checked program keeps its promise at every depth; depth zero is `idle_safe`, and depth `d + 1` is `check_sound` citing depth `d`.
  - Program 1 (`written`): `written_checked` (one residual `Apart(Lit(0), Var(0), Var(0), Var(1))`, `Span(0, k)` apart from `Span(k, m)`, and fill's precondition), `written_owed` (one `omega`), `written_safe` (in any world, citing only fill's `FnSafe`), `written_sound` (the program, every depth), `written_runs`/`written_means` (in a buffer at base 2). Control: `moved` lends the window from a word `j`; `moved_checked`, `moved_fails` (at `k = 1, m = 1, j = 0` the residual fails) and `moved_control` (the run reads 7, the meaning 5).
  - Program 2 (`returned`): `returned_checked` (the write after `Die(t)` owes nothing), `returned_sound`, `first_answers` (the callee answers `(0, 1)` relative to its reference at base 2), `returned_runs`/`returned_means`. Control: `early` moves the write before the read of `t`: `early_refused` and `early_control` (9 against 5).
  - Program 3: `liar` is declared to read and sets a cell: `liar_refused` (`None` by `refl`); `trusting_checked` (the caller's verdict is `Some`); `p3_not_ok` (`¬ProgOk`, so `prog_sound` cannot be applied); `liar_unsafe` (`¬FnSafe` of the liar at depth 1); `trusting_control` (the caller's runs differ, 9 against 5).

  **Choices** (each the sensible default; none changes the design except where §15.6's result says so):
  - One list parameter per function, so the per-object state is one object's: the holder is a counter (`Places.top`, the version bound last), and the live views a list of `LView(t, region)`, each freezing a window (`Win(lo, n)`) or the whole object (`Whole`, a view a callee answered: the signature places it only in its parameter). Several objects were the first experiment's subject.
  - Deaths are a statement `Die(t)` with no meaning and no run, standing for the site's death list; it removes `t` from the live views (`kill`).
  - The run cuts a window to its reference (`narrow`: `Ref(r.b, r.base + lo.min(r.len), n.min(r.len - lo))`), as the meaning's `window` is cut to its list, and a store or read past a reference's length does nothing or reads zero, as the meaning's `update` and `nth` do. So no bound residual arises; Rust would panic instead. Without the cut, a window past the caller's reference would reach the caller's caller's memory, which the meaning cannot see.
  - The residual is a sum: `Apart(lo, n, lo2, n2)` (a write or a lent window apart from a live window; decided where all four atoms are literals) and `Pre(g, args)` (the callee's precondition at the call's words). The "below a window's length" residual the issue expected did not arise, by the cut above.
  - A precondition is `pres(g): List<Nat> → Type`, the proof parameter of §15.8, not data the checker reads. A function's residuals are discharged under its own precondition in every world (`Checks.discharge`).
  - The signature (`Sig`) is mode, word count and result kind. The kind is checked at a call but is not load-bearing: `FnSafe` gives both a word and a view.
  - Recursion is allowed: `world` cuts calls at a depth, and `prog_sound` holds at every depth.

  **The refuting conditions.**
  1. *Does the caller's proof need more of a callee than its signature and `FnSafe`?* No. `check_sound`'s only premise about a callee is its `FnSafe`; the world is abstract, so no body is reachable. `written_safe` shows it at an instance: the caller's promise in any world from fill's promise. One limit, not a refutation: `FnSafe` has a precondition and no postcondition, so a caller's residual that needs a fact about a callee's answer cannot be discharged (`Checks.discharge` is quantified over every world). Filed as [[ownership-fnsafe-postconditions]].
  2. *Is the simulation through `put_window` after `window` costly enough that eager write-back is the wrong meaning?* No. The write-back is one lemma, `written_back` (`OnRef` of the caller, then `OnRef` of the callee on the narrowed reference, give `OnRef` of the value with the window put back), and its parts. Fresh, they cost the gate about 1.5M and 0.6M kernel steps (`written_back`, `written_at`) and a few seconds of elaboration, once, beside about 1.7M for `narrow_window`, which is the window and not the write-back. A program's instance pays nothing for it (`written_sound` is 108 steps). Stated inline in the first `Sim::lent`, the same proof took 10.5 s and 5.2M steps; split as `docs/proof-patterns.md` §2 says, `Sim::lent` is 0.3M.
  3. *Does rebasing a returned view need data the signature does not hold?* No. The caller adds the base of the reference it passed (its own) to the relative words the callee answered; the proof uses `view_in` and `view_reads` of the callee's `Safe` and nothing else (`Sim::viewed`).
  4. *Is the frame conjunct too weak for a window of a window?* No, with one condition: the callee's promise must say its value has its window's length (`OnRef.len`). With it, the caller's "outside my reference nothing changed" and the callee's "outside my window nothing changed" compose pointwise (`written_back`). Without it a meaning answering a longer list would make `put_window` write past the window. Stated as an equation of files instead, the promise would be the same statement.
  5. *Does the kernel's cost of evaluating `check` grow with the call depth?* No. `check_fn` reads only signatures. Measured on a chain (the function at depth `d` lends a window to the one at `d - 1`), with the signature table written out in the statement: 1.2k, 1.4k, 1.8k, 2.6k, 4.1k, 7.2k, 13.4k and 25.9k kernel steps at depths 2 to 256. The same with the callee at index 0 of a table of the same size: 1.2k, 2.5k, 6.8k and 24.1k at 2, 16, 64 and 256. So the growth is the table's own size in the statement, about 95 steps per signature, and the lookup by position adds about 7 per entry; depth adds nothing. Built inside the statement by repeated `++`, the table cost quadratically (45k at depth 128). Recorded in [[place-check-name-lookup-cost]].
  6. *Is the place-state invariant, weakened, enough?* Yes, and between statements it did not need weakening. A loan here lasts one statement, so no window is `out` between statements: `Sim.on` says the file holds the holder's value in the reference and its first contents elsewhere, and each live view reads its value (`Sim.views`). Inside the call's step, the weakened invariant is exactly two `OnRef`s: the caller's buffer holds the holder's value outside the out window, and the out window holds what the callee left (`written_back`'s premises). Two place facts were added: a live view lies inside the span its region freezes (`ViewOk.within`), and a read parameter comes back unchanged (`Safe.keeps`, which `liar_unsafe` shows is what a lying signature breaks). No separation algebra, history or ghost state.

  `view_in` ("a returned view lies inside the reference") is used only to show the new view lies inside the whole-object span it freezes. No frame in this fragment needs it, because a whole-frozen object is not written while the view lives; a finer returned region would make it load-bearing.

  **Not used.** The proof cites no lemma of `path.hthr`, `list_path.hthr`, `vector_path.hthr` or `span_set.hthr` beyond `Span::has`, `apart` and `Within`, which `omega` reads. The write-back is `put_window` on values (`list_window.hthr`'s `nth_put_window_before`, `_inside`, `_after`, `len_put_window`, `put_window_nil`), and the run's frame is pointwise over buffer positions; `Path::window`'s lens over `[A; n]` would add the vector's typed length, which `OnRef.len` already states. Nothing was added to those modules.

  **The lookup cost** ([[place-check-name-lookup-cost]]). Measured per `docs/proof-patterns.md` §7, fresh `--cache-dir`, steps from `--timings`, on programs of alternating set and get of one object, at 16, 32, 64, 128, 256 and 512 statements. The first experiment's `check`: 9.5k, 20.8k, 50k, 136k, 414k, and at 512 out of fuel at 2.4M (ratios 2.2, 2.4, 2.7, 3.1). This experiment's `check_fn`: 6.7k, 12.9k, 25.3k, 50.1k, 99.8k, 187.6k (ratios 1.9 to 2.0): linear. With a view taken, written beside, read and dying every four statements: 7.9k to 229.6k, linear; with 16 to 512 calls each owing a precondition: 20.4k to 615.4k, linear, about 1.2k steps a call. The representation: the holder is a counter compared by `same` against literal names (which the kernel's numeral runs cancel cheaply), there is no plan and no holder table (one object), and the live views are a list that deaths shrink, so a write scans only live views, which is the one cost the checker owes. What this does not test: several objects, whose holder table and plan would want a map keyed by buffer (`NatMap`); see [[place-check-name-lookup-cost]].

  **Kernel cost of the proof.** The module and its probes elaborate in about 30 s on a fresh cache, library prefix included. The dearest declarations are `step_mut` (5 s, mostly elaboration), `narrow_window` (3.4 s), `written_back` (2.8 s) and `written_at` (1.8 s).

The third defect on `forded/declared-index-tags`'s curve, named by [[family-types-as-code-defs]]'s implementing round (2026-08-05) after the code definitions moved every other forded family and left this one at slope 2.61 -> 2.62. **(Attribution corrected 2026-08-06 — that fixture is route 1, not forded; see the Log. The code-level cost below stands, measured now by `declared-index-branching` and `computed-arms`'s residual.)**

`Term::Supf`/`Term::ElimWf` carry `shape: Rc<Type>` — the `Wf`'s **shape component** (the sum-of-Σs), not the whole `Wf` (`crates/kernel/src/term.rs:514`). The registered codes (`SkelCode`/`IdxCode`, `crates/elab/src/gendefs.rs`) name whole types, so an `El (code^δ)` reference cannot fill a shape slot: decoding the whole-type reference yields a `Wf` whose shape is `El` of the *inline* shape code, which is no smaller. The design's §1.4 `Supf`/`ElimWf` bullet (`docs/family-type-code-defs-design.md`) was therefore unimplementable as written, and those slots were left inline — the one deviation of the implementing round.

Where it costs: the `sup_f` the declared-index inversion rebuilds per index branch (`zj` in `forded_arm_a_decl`, `crates/elab/src/forded.rs`) carries a Θ(n) shape annotation and is instantiated several times per branch (equation domain, motive instantiations, no-confusion transport) across Θ(n) branches — Θ(n²) emitted per form-A arm, which is exactly `declared-index-tags`'s unmoved exponent. The skeleton-side twin (`Supf` per constructor value / arm rebuild, `ElimWf` per match) is the residual over `computed-arms`'s 2.54.

The fix shape, if a round takes it: a **shape code** definition per declaration (`D#shape := ⌜shape⌝`), spelled `El (D#shape^δ)` in the slots — same gate, same best-effort discipline, and the kernel is already indifferent (typing builds a `Type::Wf` from the slots and hands agreement to conversion; the ι-rule only clones them). Whether the conversion side then pays repeated δ+decode per unfold instead — the other candidate reading of the unmoved slope, since the gate is 95–98% of these fixtures — is the first thing that round should measure before writing anything.

## What it assumes from elsewhere

- **[[family-types-as-code-defs]]** owns the whole-type code scheme and the recognizer's nominal branch. Assumed here: only that `SkelCode`/`IdxCode` stay whole-type codes.

**MEASUREMENT FIRST, as the charter required, and it moved the design.** Per-slot counters at the two kernel-gate sites, on the `ir_v1` declarations prefix, prefix + `certgen_cert`, prefix + `certgen_code`:

1. **The slots ARE the workload now**: 68-77% of every emitted node — statements and bodies alike, all three workloads — sat inside a `shape` or `arity` slot of `Supf`, `ElimWf` or `Type::Wf`. The two prior exonerations were correct when taken; they predate the component-respell round removing everything else.
2. **The ARITY is the bigger half, by ~3.5x** — every prior sentence on this issue says "shape slot". It is also written in more places: the step telescope puts the whole arity term in a `Vec` length, a `Fin` length and an `nth` length, once per arm.
3. **`Type::Wf`'s own slots outweighed both formers** (4,694 occurrences / 57% of body mass in the prefix alone) — and byte-comparing them against the registry's copies showed they were **whole registered lowerings emitted verbatim at sites that call no respell**: the two `match` lowerings' spines and the motive with a non-declaration head. That is [[wf-field-conversion-cost]]'s residual, not this issue's slot, at the same measurement.
4. **Half of a value-heavy statement was in the kernel's DECODE spelling.** `El (D#tycode^δ)` whnfs to `Wf(El ⌜S⌝). n` — the lazy decode leaves every component `El`-wrapped — and that is what a constructor value built at a *respelled* expected type carries into all its annotations. Every guard in the elaborator compares against the registry's INLINE copy, so every one of them declined: the predecessor's value-side respells were, at those sites, dead. The statement cascade made this common; nothing had measured it.

**WHAT LANDED** (five mechanisms, one wiring surface):

1. `GenDef::ShapeCode(tag)` = `D#shape : Trm_c(· ⊢ Ty l) := ⌜S⌝` and `GenDef::ArityFn(tag)` = `D#arity : Π(x : El (D#shape^δ)). Nat := λx. n`, registered off `register_ty_code`'s own lowering for a **recursive** declaration (its boundary inherited verbatim), all-or-nothing, guarded at every use site by `Elaborator::wf_slot_refs`'s structural comparison against the inline pair — **plus the decode spelling `El ⌜S⌝` as a second accepted shape copy** (finding 4; without it the value site declines silently and statements do not move at all — measured). The arity is a **function, not a code**: the slot holds a `Term` of `Nat` under the shape's binder, so the only closed thing that reduces back to `n` there is `app(D#arity^δ; x₀)`.
2. Spelled at: `build_ctor`'s `Supf` (values), `build_elim_wf`'s `ElimWf`, `forded_arm_a_decl`'s `zj` (this issue's original site), and — through `wf_step_telescope_at`'s new `slots` parameter, the one-line edit the issue predicted, **widened by measurement from the `Supf` to every arity the telescope writes** — the `Vec`/`Fin`/`nth` lengths. Kernel callers pass `None` and are unchanged.
3. `Elaborator::whnf` now maps `El (D#tycode^δ)` to the **registry's inline copy** rather than the kernel's lazy decode (finding 4's fix). Same type, and it restores the invariant every structural reader and every guard is written against — `unspell_ty_deep`'s doctrine one step earlier, at the choke point every structural read goes through.
4. Both `match` lowerings take an **emission copy of the spine** (`respell_spine`, already written for values) for `Case` component types, `Inl`/`Inr` annotations and branch injections; binder types and everything `projection`/`elab_arm` reads stay inline.
5. `build_elim_wf`'s motive respell goes **component-wise** (`respell_ty_deep` at depth 1): a `fn` returning a function (`pick_arm(arms: Ir) -> Nat -> Ir`) has motive `Π(Nat). ⟦Ir⟧`, on which the whole-type respell declined.
